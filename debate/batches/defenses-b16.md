## A1
DEFENSE: Certificates are per state, not per bundle: "certificate = (state, weights hash, facts-table version)" (R3), and under R135 "a patched runtime inherits a state's certificate if, on that state's full retained gold set plus canary corpus, outputs are bitwise identical"; only diverging states recertify and "run on fallback meanwhile". So nothing uncertified ever faces the public. A missed stop phrase is fixed the same day without a finetune: "Stop = union of deterministic lexicon (incl. dialect patterns) and Needle GLOBAL", and the "post-call DNC sweep of every transcript before any redial" catches what slips through. GLOBAL is "versioned separately" (R34), so a stop fix never touches LOCAL certificates. Adding to a union can only add stops, never remove one. That is a one-way change for harm.
EXISTING ELEMENTS: R3 certificate key; R135 equivalence-based re-keying; R34 GLOBAL pass versioned separately; stop = lexicon ∪ GLOBAL (R66, R93); post-call DNC sweep; R124 staged ramp (canary cohort with 100% audit); "states that can't reach the bound stay on deterministic fallback".
NEW HARDENING: NEW "monotone patch" class. A release that only adds lexicon rows or OR-combines a new GLOBAL stop detector with the old one inherits the Tier A false-continue certificate. The proof is a replay over all retained audited audio: the new stop set must be a superset of the old on every turn. Only the false-stop rate, a business cost and not a harm, is re-measured live. Finetunes of the LOCAL weights stay on the full R124 ramp.

## A2
DEFENSE: Exclusion by ZIP or surname is already illegal inside this design. R46's "product-policy table (all options to all, non-protected keys only); prohibited-basis field tags + build invariant" fails any selector keyed on a proxy. A group that cannot yet reach its bound is not dropped: "states that can't reach the bound stay on deterministic fallback (callback or human)", and R121 and R147 send repeated-unintelligible calls to a human, never out of the campaign. R131 already admits that group labels are not runtime inputs. It uses a "label-free worst-group check" over acoustic and ASR-confidence clusters, which has power because clusters are large. Small groups also feed R147's consented strata.
EXISTING ELEMENTS: R46 prohibited-basis tags + build invariant; R131 strata + label-free worst-group cluster bound; R121 accessibility routing; R147/R111 speech-disability strata, human-only next contact; deterministic fallback for uncertified states.
NEW HARDENING: NEW (1) The prohibited-basis invariant extends to campaign and dial-list selectors. Only consent, DNC, registration and suitability keys may filter, and a ZIP or name-derived filter fails the build. A reach-parity report compares dialed share with the consent pool by census tract. (2) The per-group blocker is redefined as the pooled absolute bound, plus per-group non-inferiority on turn-level Tier A rates (many events per call, so they have power). A group with too little evidence gets acoustic-condition routing: low ASR confidence or the worst cluster goes to a human. Nobody is excluded.

## A3
DEFENSE: The mechanism the attack names, ASR and clarify routing, is already measured at high base rates, where power exists. R111 makes "per-group false-unintelligible, false-vulnerability and fallback rates release blockers". R121 tracks "Reached quote or human" parity, and R131 holds the worst acoustic cluster to the same bound. Fallback is not a dead end. It is a "warm transfer or booked consult" (R56) in which a human quotes from the same R46 product-policy table. So "callback instead of quote" is a delay, not a different menu. Matched pairs test the menu, and process rates test the routing. Outcome-level fair-lending tests belong to the lender, who "runs application and decisions".
EXISTING ELEMENTS: R46 matched-pair tests + path-divergence Tier A metric; R111 per-group fallback rates as release blockers; R121 "reached quote or human"; R131 worst-cluster bound; R56 request_human; R163 independent outcome feeds.
NEW HARDENING: NEW (1) A time-to-quote and quote-reached rate per acoustic cluster and per stratum, as a release blocker. This is the process proxy that sits upstream of close-rate gaps. (2) Outcome disparity is tested quarterly with hierarchical pooling across states and quarters, using CUSUM, in a firewalled fair-lending enclave with counsel. Proxy methods are kept out of CRM and runtime, as R131 requires. (3) Any cluster gap above threshold sends that cluster to a human with priority.

## A4
DEFENSE: Labelers are not doing a vigil over 10-minute calls. R143 gives them "only the clipped turns under audit", and the queue is "all disagreements + random agreements" (R2), so attention goes where harm is likely. Human labels are also not the only detector. The "post-call DNC sweep (lexicon + GLOBAL re-run)" runs on 100% of calls, R132's label-free monitors run on 100% of traffic, and R113 bounds harm "with outcome proxies (later complaints, repeat DNC requests, rescissions)". R131 already measures inter-rater agreement with "two trained auditors" and corrects with the confusion matrix. A 1-in-20 human miss must also coincide with misses by the lexicon, GLOBAL and the downstream channels.
EXISTING ELEMENTS: R143 clipped-turn audits; R2 disagreement-weighted audit; R131 two auditors + confusion matrix; R66 post-call sweep; R132 100% label-free drift monitors; R113 outcome proxies; R97 extra sampling where models agree.
NEW HARDENING: NEW Measured recall. (1) Seeded gold harms (real-audio stop and decline clips from the regression suite) go blind into every labeler queue at about 2%. Per-labeler recall is tracked, and the published bound is the labeled bound divided by the lower confidence bound of recall. (2) A capture-recapture estimate (human, sweep, complaint channel) of true harm. (3) Double listening only on stop-adjacent windows (the R108 token list), not whole calls. Overhead is a few percent, not 2x.

## A5
DEFENSE: A rate change is a value change, not a decision change. "Fragments hold no literal numbers; every fact token is a table key" (R91). Needle's input is the caller turn plus a tool schema, and no tool sets price or credit facts (writer allowlists). A new APR row therefore leaves every Needle output and every transition bitwise identical, and R135 re-keying lets states inherit when "outputs are bitwise identical" on gold replay. What does depend on the value is deterministic: Reg Z lints, the calculator, and the R105 "pre-render every fact-bearing clip... pinned-ASR round-trip check". All of these run in minutes. Lender terms come from the "versioned lender rate sheet" (R32), and the lender decides.
EXISTING ELEMENTS: R91 no literal numbers/table keys; writer allowlists (R5); R135 equivalence re-keying; R105 pinned TTS + audio round-trip; R32 lender rate sheet; R140 forward-only policy table with effective windows; R155 typed incentive rows.
NEW HARDENING: NEW Row changes are typed. A value-only change keeps the same key, unit and spoken form and stays within the row's declared certified range. It re-certifies automatically through lints, calculator property tests, the audio round-trip and bitwise gold replay, with no new audited calls. A structural change (new key, new wording, a value outside the range, a new trigger term) expires the certificate. "Expire" now means re-validate, and audit is needed only for structural change.

## A6
DEFENSE: The 60% hang-up premise belongs to cold lists. This dial list is "limited to prior-express-written-consent and inbound/warm leads" (R59), and the consent names "seller + AI voice", so the callee agreed to exactly this call. They see "branded caller ID + A-level STIR/SHAKEN + Free Caller Registry" before answering. R142 enforces "pacing 1:1 by default, with no overdial", and frequency caps keep per-number volume low, which is what analytics engines score. R59 already runs "answer-rate/spam-label monitoring per number". The preamble opens with the company and purpose, so the expected caller identifies itself first. Disclosure is a legal floor, and a design that skipped it to save reach would be the real failure.
EXISTING ELEMENTS: R59 consent-only list, branded caller ID, STIR/SHAKEN A, Free Caller Registry, spam-label monitoring; R142 1:1 pacing; R109 abandonment cap; frequency caps; PREAMBLE (compiled, unskippable).
NEW HARDENING: NEW (1) No number rotation. A fixed, registered, branded pool sized to volume, with a per-number daily dial cap. (2) Short-duration hang-up rate and analytics-label status per number become a throttle input to the dial permit (R138). (3) At consent capture, the lead picks a call window and is told the number. Where email consent exists, a pre-call notice (texting-hours gated) says when the call will come. (4) A preamble lint caps total length, with the R31 seller and "you asked us to call" segment first.

## A7
DEFENSE: The design does not send these messages over a low-trust 10DLC brand. R89 sends "outbox text from registered short code", and R115 names "SMS short codes" as the channel, which are not subject to T-Mobile's 10DLC brand daily caps. Volume is small: only commits send envelopes, a few percent of calls. A miss is not a lost sale. WAITING_FOR_SIGNATURE has "timer and handlers for BOOKED/CONFLICT/TIMEOUT/ERROR" (R55), "help_with_screen offers resend/wait/callback" (R60), the state is SALE_PENDING, and R120 offers "mailed or consultant-assisted signing". DNC-policy copies already have email and "print-and-mail API" routes (R84).
EXISTING ELEMENTS: R89/R115 registered short code; R55 WAITING_FOR_<effect> substates; R60 resend/wait/callback, SALE_PENDING; R120 paper/consultant signing; R84 print-and-mail outbox; R22 OTP to dialed number; R122 registration guard on SMS.
NEW HARDENING: NEW (1) SMS capacity becomes an admission token, like R142's Needle capacity token. Entering QUOTE reserves an envelope-and-OTP message budget, and with no budget the call goes to callback signing. (2) The outbox has priority classes: OTP and envelope first, informational copies by email or mail. (3) The transactional OTP short code is kept apart from any marketing traffic, with link-free OTP templates. (4) Carrier delivery receipts become WAITING_FOR events, and a missing receipt triggers the e-sign vendor's voice or email OTP fallback.

## A8
DEFENSE: Most of the flush is already blocked. R55 "holds + idempotency keys" stop duplicate retries. R122 makes registration "a pre-dial and outbox guard, with texts counted as solicitation". R149 "extend[s] the consent gate to every outbound SMS and email". R139 pins tzdata and fails closed on clock uncertainty. OTPs have a TTL bound to the session, and the session's WAITING_FOR_SIGNATURE has already timed out (R55), so a stale OTP has no live state to serve. The gap is real in one respect: the calling-hours check sits on the dial gate, not at outbox send time.
EXISTING ELEMENTS: R55 idempotency keys + WAITING_FOR timeouts; R122 outbox guard, texts as solicitation; R149 consent gate on all outbound; R139 pinned tzdata, fail-closed time; R41 lawful-window clamping; regulation profile, most restrictive wins.
NEW HARDENING: NEW (1) Every outbox effect carries [not_before, not_after], computed at enqueue by the same pinned-tz calling-hours gate for the most restrictive candidate jurisdiction (FTSA 8am-8pm in FL). The executor re-checks at send time, not at enqueue. (2) A model-checked invariant: no SMS or email effect is released outside its window. (3) Expired session-bound items (OTP, envelope) are never sent late. They are re-planned as one next-day, in-hours "your documents are ready" message or a human callback. (4) After an outage, the drain is rate-limited and deduplicated by idempotency key.

## A9
DEFENSE: "'No data' = no dial" is deliberate fail-closed design, consistent with R114 ("do not dial when a list is stale or unavailable"). The volume math assumes 15 blind attempts. R142's 1:1 pacing, frequency caps and consent-only warm leads (R59) keep attempts per contact low. Pre-2021 consent dates are not a cost of this design: leads with consent that old fail the consent ledger's freshness requirement anyway. RND data changes only when carriers report, so an answer is valid for one data release, not for one dial. The dial permit (R138) needs a current answer, not a live query.
EXISTING ELEMENTS: pre-dial gate RND ("no data" = no dial, R73); R114 fail closed on unavailable lists; R138 linearizable dial permit; R142 admission control and pacing; R59 consent-only leads; INBOUND_OPEN entry (R30).
NEW HARDENING: NEW (1) An RND cache keyed by (number, consent date, RND data release). The next day's dial list is batch-queried off-peak, and the permit reads the cache. A 6pm outage then changes nothing while the release is unchanged. If the current release cannot be confirmed, the gate fails closed. (2) Leads that return "no data" are not wasted. Where email consent exists, they get an invitation to call in (INBOUND_OPEN), which needs no RND safe harbor. (3) The query budget is sized against the number of unique numbers per release, not attempts.

## A10
DEFENSE: Outbound means the operator controls arrivals, which is unlike the inbound call centers Erlang C usually models. R142 already ties every "dial permit" to "a reserved Needle capacity token from live fleet health", so new dials stop first and in-flight calls keep priority. Fallback is "callback or human", and R56 transfers warm only "if open, else book consultant call + send written proposal". A fleet-wide ASR shift is caught by R137 (channel class in the certificate key, uncertified class goes to callback fallback), by R132's 100% drift monitors, and by the daily golden-audio canary. The surge becomes bookings, not hold queues.
EXISTING ELEMENTS: R142 admission control; R56 request_human with booked consult; R137 channel-class certification; R132 label-free drift monitors; daily golden-audio canary; R121 human-only routing; "clarify once, then fallback".
NEW HARDENING: NEW (1) A human-capacity token. The dial permit also reserves expected fallback load, computed from the live fallback rate times the transfer share, against staffed closer headroom (Erlang C target wait). A rising fallback rate throttles dialing within seconds. (2) A drift alarm in a time zone pauses new dials on the affected channel class. (3) Warm transfer only when a closer is free now. Otherwise the caller gets an immediate concrete booked slot, never hold audio. (4) Closers are staffed for the expected fallback rate, not the worst case.
