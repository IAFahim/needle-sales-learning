## A1
DEFENSE: The design never uses history pseudostates. A detour is just the root handler: R192 requires that for every state and every GLOBAL event the effective handler is the root GLOBAL handler, checked on the enumerated binary relation (R134). In the scenario, the Fresno remark is itself a GLOBAL event. jurisdiction_changed is "fired on any stated residence change, validated or not" and "re-evaluates hour/attempt/disclosure guards -> WRAP_UP" (R70). R189 makes GLOBAL multi-label, so it fires alongside request_caller_identity, in a fixed order. R211(2) adds a second net: a property other than the lead's means "Are we talking about the home on <street>?" and, on a mismatch, lead-gen. R58 means one turn makes at most one transition, evaluated against the start-of-turn state. So no unguarded return to QUOTE happens in the same turn.
EXISTING ELEMENTS: R192 per-pair root-handler invariant; R134 enumerated binary relation diff; R70 jurisdiction_changed re-evaluates guards -> WRAP_UP; R189 multi-label GLOBAL with fixed order; R211 property address mismatch -> lead-gen; R58 one turn -> at most one transition; R47 lead-gen invariant blocks on-call price states
NEW HARDENING: NEW: A lint bans shallow and deep history (H/H*) in the graph. Every return from a GLOBAL detour re-enters through the parent's entry choice point, so every admission guard (lead-gen mode, jurisdiction profile, suitability) is evaluated again on the current slot store. Model-checked invariant: every entry edge into a QUOTE/READ_BACK/COMMIT substate carries the full admission guard conjunction. No unguarded edge may exist.

## A2
DEFENSE: Timers are not free-floating user variables here. Silence is a deterministic front-end event: "silence as deterministic events (no_speech_after_answer, silence(duration_bucket))" (R65). Waits are explicit graph substates: PAUSE, HOLD and WAITING_FOR_<effect> "with timer and handlers" (R55, with a build completeness check). An event is delivered to whatever state is current. Once sensitive_event has exited READ_BACK, a silence event lands in the scripted exit, which "no pitch" makes structurally unable to offer an agreement (R19). R193 events "carry a session epoch, and stale ones are dropped". Every utterance is a fragment certified by id, and R172's status-claim lint is keyed to state. So in our design a READ_BACK re-prompt fragment cannot be rendered from an exit state.
EXISTING ELEMENTS: R65 silence(duration_bucket) events, PAUSE/HOLD substates; R55 WAITING_FOR_<effect> timers + build completeness check; R19 sensitive_event scripted exit, no pitch; R193 single-writer mailbox with session epoch, stale events dropped; R172 status-claim lint keyed to state; fragments certified by fragment id
NEW HARDENING: NEW: (1) Every timer is a (state-id, epoch)-scoped event armed by the runtime, never a slot. Leaving the arming state cancels it, and any event whose state-id differs from the current state is dropped. (2) A build-time fragment-to-state allowlist: each fragment id is legal only in listed states. Exit states (sensitive, stop, cancel) allow only their own fixed fragments, enforced in the runtime renderer, which fails closed. (3) A fault-injection test fires every armed timer after every GLOBAL exit.

## A3
DEFENSE: QUALIFY does not choose between ROOF_FIRST and NOT_SUITABLE with two overlapping graph guards. Per R71, the "versioned compliance-owned suitability table -> NOT_SUITABLE (honest polite exit, no rebuttal) or ROOF_FIRST" returns one outcome per call from the table. The graph switches on that single enum, so edge priority cannot flip the policy. The table is versioned, and "changing a row decertifies every branch that cites it". Unsuitable closes are Tier A harm in the per-call budget (R71), so a release that flipped the outcome would fail certification on audited real calls. The success label requires passing a sampled suitability audit. Also, R134 diffs the compiled (state, event, abstract-guard) relation against the exported graph, so a redrawn order shows up as a changed relation.
EXISTING ELEMENTS: R71 suitability table -> single outcome, unsuitable close = Tier A harm, sampled suitability audit; facts table row change decertifies; R134 binary relation diff; R6 per-state precedence canonicalization; R150 payment <= savings row
NEW HARDENING: NEW: (1) Suitability rows carry a fixed severity order (NOT_SUITABLE > HOA_APPROVAL_FIRST > ROOF_FIRST > OK), and the table returns the most severe match. (2) A build check proves that outgoing guards at every choice point are pairwise mutually exclusive and jointly exhaustive over the abstract guard domain (SMT), so behaviour-order prefixes can never decide an outcome. (3) A golden suitability regression suite is replayed every release, and any changed outcome blocks release until compliance signs off.

## A4
DEFENSE: The commit is bound to content, not just to having visited READ_BACK. R23: "Read-back bound to config hash; any change after read-back forces a new read-back." R49: "accept_offer commits only the quote hash read back immediately before the yes". R134 adds an independent outbox monitor that refuses CONTRACT_SENT unless the trace has READ_BACK "with a playback-engine completion mark for the same quote hash". In the scenario, read-back #2 was interrupted: mandatory segments count only on uninterrupted playback (R39). The commit question plays only after the last segment (R106), and AWAIT_* is entered only when it finishes (R14). So there is no open question to affirm. "Yes, yes, the one you said first" also fails the short direct-affirm check (R81), and R144 makes the commit prompt "say 'send the contract'".
EXISTING ELEMENTS: R23 config-hash-bound read-back; R49 commits only quote hash read back immediately before the yes; R134 outbox trace monitor (same quote hash); R39 mandatory segments uninterrupted; R106 separate commit-question fragment; R14 AWAIT_* after playback; R81 short direct answer turn; R144 action-production prompt; R4 reference resolution -> clarify
NEW HARDENING: NEW: The read-back question id is instance-scoped: qid = hash(quote_hash, read-back nonce). The commit gate accepts an affirm only for the current qid, and only if its quote_hash equals the slot-store version being committed. A back-reference ("the first one") in AWAIT_CONFIRM routes through the R4 resolver to a new read-back of that option. It is never a commit.

## A5
DEFENSE: The premise is not our design. R69 counters are "total turns, per-state visits, backtracks, repeated objections, wall-clock -> WRAP_UP". Total turns and wall-clock count every turn, GLOBAL detours included. Per-state visits catches the ping-pong by counting re-entries into QUOTE and CLARIFY_PRICE, and no entry action zeroes them. dispute_prior_statement is a backtrack-class event, so the backtrack counter climbs too. "Clarify once, then fallback" is a call-level rule, and repeated unclear() feeds the vulnerability counter -> NO_SALE_SAFE_EXIT (R15). The design already anticipates the abstraction gap: "slot abstraction for model checking audited against live calls" (R49), plus property-based random walks over loops. R132's label-free monitors (clarify rate, CUSUM) would flag a 40-minute call.
EXISTING ELEMENTS: R69 budget counters incl. total turns, per-state visits, backtracks, wall-clock -> WRAP_UP; R15 vulnerability counter -> NO_SALE_SAFE_EXIT; R49 slot abstraction audited + random walks over loops; R132 drift monitors on clarify rate
NEW HARDENING: NEW: (1) Budget counters are root-owned, monotonic call-scoped variables. A lint fails the build if any entry, exit or transition action writes to them except to increment. (2) The checker models them concretely: their bounds are small, so an explicit-state check over (state, counter vector) is exact, not abstracted. Liveness property: every path reaches WRAP_UP/END within the bound. (3) The wall-clock cap is also enforced by a runtime watchdog outside StateSmith.

## A6
DEFENSE: "No pitch after decline" is already a model-checked whole-graph invariant (R21), and it is exactly the "after stop, no sales state reachable" property. A stop is not a pausable sequence either. Tier 1 stops "end immediately" (R24). The DTMF stop does "DNC write, fixed confirmation, hang up" (R75), and leave_taking "hangs up, with no question and no pitch" (R164). R189 orders the DNC write first, and "any transfer carries the DNC flag and is service-only". So request_human inside the exit cannot reach a closer. R138's dial permit reads the DNC ledger. A history return to QUOTE would also violate R21, which is checked on the compiled relation (R134).
EXISTING ELEMENTS: R21 invariant no pitch after decline; R24 Tier 1 end immediately; R75 DNC write, fixed confirmation, hang up; R164 terminal fragment + hang up; R189 DNC write first, transfers service-only with DNC flag; R138 DNC in dial permit; R134 relation diff
NEW HARDENING: NEW: Terminal exits (STOP, CANCEL, SENSITIVE, LEAVE_TAKING) sit in a TERMINAL region that is a sibling of the SALES region, so root GLOBAL handlers are not inherited. Each terminal state handles identity/human questions with fixed answers and then proceeds to hang-up, with no return edge. Invariant written over a flag, independent of state names: AG(dnc_flag -> AG ¬(sales_fragment ∨ sales_transfer)). R192's per-pair check is scoped to the SALES region.

## A7
DEFENSE: The key safety check does not depend on state names. R134's independently written outbox monitor "refuses CONTRACT_SENT or any commit effect unless the committed trace contains READ_BACK with a playback-engine completion mark for the same quote hash". It keys on effects, so a fast path to COMMIT_LOAN gets refused at the outbox. Tool exposure is generated, not hand-named: "tool lists derived from handlers (build fails on offered-but-unhandled)" (R52), and "commit tools exist only in post-read-back states" (R27). R85 phrases the invariant as "every path to any commit state", meaning a class, not a string. Matched-pair tests, random walks (R49) and Tier A certification on real calls cover any new state. A split state starts uncertified and runs on fallback.
EXISTING ELEMENTS: R134 outbox trace monitor keyed on commit effects + quote hash; R52 tool lists derived from handlers; R27 commit tools only in post-read-back states; R85 every path to any commit state passes READ_BACK; R49 random walks; R3 certificate per state (new states uncertified -> fallback)
NEW HARDENING: NEW: (1) Properties are written over derived predicates, not names: commit_state(s) := s exposes any tool tagged commit/effect class. (2) Vacuity checking is on: every property's antecedent must have a reachability witness, or the release fails. (3) A coverage check: every state exposing a Tier A tool or effect must be covered by at least one property, and a state set that changes between releases forces property-file review.

## A8
DEFENSE: The graph and the table can't silently drift apart. The facts table is in the certified bundle, and "certificate = (state, weights hash, facts-table version)" (R3). "Changing a row decertifies every branch that cites it", and certificates "expire when a cited policy row changes". Adding SLATE/WOOD_SHAKE rows expires QUALIFY's certificate, so it runs on deterministic fallback. Reissuing a certificate means replaying gold sets under the new table (R3). R140 continuously re-checks bundles "as compatible with that table" (lints, fact-key coverage); otherwise QUOTE/READ_BACK "drop to lead-gen or callback fallback". The suitability decision itself comes from the table (R71), not from a graph switch on roof material.
EXISTING ELEMENTS: R3 certificate keyed on facts-table version; row change decertifies citing branches; R140 table compatibility re-check -> lead-gen/callback fallback; R71 table-owned suitability outcome; R211 roof cross-check vs permits; final plan: bundle content-hashes policy table
NEW HARDENING: NEW: (1) A build and runtime exhaustiveness check: every guard switching on a table-owned enum must cover the current table's full value set. A value unknown to the graph raises UNKNOWN_CATEGORY -> human review/NOT_SUITABLE, never a default. (2) A lint bans `else -> QUOTE` (or any sales-forward default) at policy choice points. Defaults must be fail-closed. (3) Adding a table enum value is a schema change that forces graph regeneration.

## A9
DEFENSE: Effects in this design are never fired directly. They are intents appended to the outbox and "drained only on committed turns" (R13). The outbox has its own gates. R149 extends "the consent gate to every outbound SMS and email". R189 handles a multi-intent turn in a fixed order: "DNC write, then cancel", so the DNC/cancel record exists before the turn commits. R122 makes registration an outbox guard. R216 makes CANCEL a saga with an invariant against further action while a cancel is open. R173 says a cancel hit voids the envelope through the vendor API. R196's SMS budgets add another check. The reminder intent reaches a drain that sees a revoked contact and refuses it.
EXISTING ELEMENTS: R13 effects as outbox intents, drained on committed turns; R149 consent gate on every outbound SMS/email; R189 fixed order DNC write then cancel; R122 SMS effect guard; R216 CANCEL saga; R173 envelope void; R115 revocation intake bus; R196 SMS budgets
NEW HARDENING: NEW: (1) A lint bans effect intents in entry and exit actions. Effects may appear only on named transitions, so every GLOBAL edge is free of them. (2) The outbox drain re-reads the DNC/cancel/revocation ledger at send time and tags each intent with purpose. Any marketing or sales-purpose intent in a turn carrying a stop/cancel/sensitive event is dropped, while compliance confirmations alone pass. (3) Model-checked property: no sales-purpose effect intent in a turn with a stop or cancel.

## A10
DEFENSE: The time guarantees don't rest on the untimed proof. The design enforces them in deterministic runtime code. R69's counters include "wall-clock -> WRAP_UP". Stops "end immediately" (R24), within ten seconds. The abandonment threshold is a per-call measured invariant: "first PREAMBLE segment starts within about 1.5 s" plus a 30-day counter (R109, R142). R139 gives the dial gate pinned tzdata, authenticated time and a guard band. R70 and R183 re-evaluate hours guards mid-call on a jurisdiction or location change. The R122 outbox guard treats texts as solicitation, and R149 gates every SMS. Note that 64.1200(c)(1) governs initiating solicitations, so a 9:03 pm SMS is a new initiation and gets its own guard.
EXISTING ELEMENTS: R69 wall-clock budget -> WRAP_UP; R24 Tier 1 end immediately; R109 1.5 s preamble deadline + abandonment counter; R142 abandonment counter, admission control; R139 pinned tzdata, authenticated time, guard band; R70/R183 mid-call hours re-evaluation; R122/R149 SMS outbox guards
NEW HARDENING: NEW: (1) The dial permit computes hours_deadline = window end for the most restrictive candidate zone (Florida's 8 pm included) minus the guard band. It refuses to dial if the remaining time is shorter than the max call budget. (2) A root timed event hours_deadline_near -> WRAP_UP with a lawful callback. The outbox refuses any sales SMS or effect after the deadline. (3) A timed model (UPPAAL) of the deadline, stop and OTP timers is checked alongside the untimed graph.
