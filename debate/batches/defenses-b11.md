## A1
DEFENSE: An HOA townhouse cannot reach install on a roof the board controls. R156 schedules "the site survey inside the cancellation window", makes "the contract contingent on a survey-confirmed price" and blocks install until then, with "roof-structure slots" and a no-penalty exit on any change order. R83 requires every material limitation from the product-policy table in each read-back, and R71's suitability table already supports pre-quote holds (ROOF_FIRST). R88's record-owner lookup on the validated address returns the parcel record, which for a common-interest development names the association parcel. The real gap: nothing asks about governance before the quote, so association approval and its conditions are never read back.
EXISTING ELEMENTS: R156 survey-contingent contract + install block + no-penalty exit; R83 material-limitation disclosures in READ_BACK; R71 suitability table / ROOF_FIRST; R88 record-owner lookup on validated address; R85 READ_BACK lint list.
NEW HARDENING: NEW: (1) A governance slot sourced from county parcel data (common-interest development / recorded CC&R flag) plus one neutral QUALIFY question ("Is your home part of an HOA or condo association?"). (2) HOA or common-element roof -> HOA_APPROVAL_FIRST suitability row: no price or close on the call; lead-gen plus written proposal. (3) Where a close is allowed, a policy-table row "association approval required; may impose insurance, maintenance and removal-for-reroof duties" is mandatory in READ_BACK and the contract, with a no-penalty cancel if approval is denied or conditioned. Install is blocked until written approval is on file.

## A2
DEFENSE: The chattel home fails the design's ownership checks before any lien is written. R159 draws identity answers "only from independent sources (public records, KYC vendor)" and runs "a pre-dial phone-to-record-owner match"; for a land-lease park the county record names the park owner, so the call is "lead-gen only". R88 runs the "record-owner lookup on validated address", and the R88 capacity flags from records and lender checks go to a human review path. The lender runs the application and decisions (R60), so a lender that will not take a real-property lien or fixture filing on HCD-titled collateral declines it, and nothing closes. R156 survey contingency covers roof structure. The real gap: the lien/UCC fragment is one wording, not keyed to collateral type.
EXISTING ELEMENTS: R159 independent identity sources + phone-to-record-owner match -> lead-gen only; R88 record-owner lookup + capacity flags -> human review; R60 lender decisions as system events; R156 roof-structure slots + survey-contingent contract; R85 lien/UCC in READ_BACK.
NEW HARDENING: NEW: (1) A structure_type slot from parcel use code and the state manufactured-housing title registry (HCD in CA), never from speech. (2) Manufactured, chattel-titled or land-lease -> NOT_SUITABLE for the residential product row, honest exit plus referral. (3) The lien/UCC READ_BACK fragment becomes a policy-table key per collateral type, selected only by the lender's stated security instrument. (4) A HUD-code roof-load row in the suitability table.

## A3
DEFENSE: Trusts are named in the design. R88: "capacity flags (conservatorship/trust/POA) from records and lender checks -> human review path", so "Trustees of the Doe Family Trust" on title sends the deal to a human, not to an automatic envelope. Nor does the envelope go to the late John: R146 says "never send a co-owner envelope to vendor-sourced contact data", R120 requires each signer to have "independently sourced contact data" and per-signer vendor ID verification for any lien, and R159 requires "lender-grade identity verification (document plus selfie or KBA) for each record owner". A dead co-trustee cannot pass that, so no lien files. The gap: the deceased check covers only the dialed lead, and nothing records the capacity a signer signs in.
EXISTING ELEMENTS: R88 capacity flags (trust) -> human review; R120 per-signer ID verification, no lien until every owner verified; R146 no envelopes to vendor-sourced contacts; R159 lender-grade ID per record owner; pre-dial deceased list.
NEW HARDENING: NEW: (1) Run the deceased-list check against every record owner on title as well as the dialed lead; a hit sets no_close and routes to human review. (2) A trust-titled property gets no same-call close: a human collects a certification of trust (CA Prob. Code 18100.5) naming the current trustees, and the e-sign signature block reads "as trustee" for each one. (3) Signer list = current trustees per that certification, verified by the lender, not the names on the lead record.

## A4
DEFENSE: This caller is never VERIFIED as the owner. R159 draws identity answers from public records, and title still names Mom, so the adult child fails the R73 challenge-response as record owner; R143 sends a partial match "to clarify or a human". R88's record-owner lookup feeds the signer list, and R120 and R159 require ID verification for each record owner, which a decedent can't pass, so no lien files. "Mom passed last year" is also a bereavement phrase: R19 puts sensitive_event(bereavement) in every state with "deterministic lexicon pre-emption", which fires on wording, not on distress, giving a condolence exit with no pitch. The pre-dial deceased suppression list covers Mom as owner. The gap: no explicit estate route.
EXISTING ELEMENTS: R73/R159 identity challenge from public records; R143 partial match -> clarify/human; R88 record-owner lookup; R120 per-signer verification before lien; R19 sensitive_event(bereavement) + lexicon pre-emption; pre-dial deceased list.
NEW HARDENING: NEW: (1) An estate lexicon (executor, estate, probate, passed, inherited) plus a Needle estate_matter GLOBAL subtype -> no quote, no close; offer a written information packet and a human consult. (2) The deceased-list check runs against every record owner on title (as in A3). (3) A property whose record owner is deceased is suppressed from sales campaigns until title is transferred, and is never reached through an heir's number.

## A5
DEFENSE: One spouse cannot sign both envelopes. R146 says "never send a co-owner envelope to vendor-sourced contact data"; the stale lead-record number gets nothing. The co-owner either self-opts in or gets a packet through a channel the verified customer chooses. R120 requires "independently sourced contact data" per signer, forbids two signers sharing a phone or email, and requires per-signer vendor ID verification for any lien envelope. R159 adds document-plus-selfie or KBA for each record owner. So the estranged spouse must independently sign, which is the written consent Fam. Code 2040 requires. R146's sensitive_event(household_safety) handles conflict cues. The gap: a pending dissolution isn't asked about, and the self-reported move horizon hides a court-ordered sale.
EXISTING ELEMENTS: R146 no co-owner envelope to vendor data + household_safety subtype; R120 independent per-signer contact + ID verification + no shared phone; R159 lender-grade ID per record owner; R71 move-horizon suitability slot; R145 second-voice -> human.
NEW HARDENING: NEW: (1) One neutral QUALIFY question: "Do you expect any change in ownership in the next few years, such as a sale, refinance, divorce or estate?" Any yes -> NOT_SUITABLE (honest exit). (2) A dissolution lexicon (divorce, separated, custody, family court) -> no close, human review. (3) The lender title pull checks for a lis pendens or family-law filing before the lien; a hit blocks the envelope. (4) In community-property profiles, a spouse not on title is a required consenting signer.

## A6
DEFENSE: The savings claim can't fill from the tenant's account. R153 makes verified_usage writable only by the utility data API or bill extractor, and "authorization must come from the utility account holder. A mismatch with the record owner routes to a written aut[horization path]", so the tenant's account is not the landlord's to authorize. R61 permits savings "only from verified bill or usage data", and R72 requires a calculator_output with a substantiation id. On Reg Z, R60 has the lender run the application and decisions, and the lender classifies loan purpose; R17's packet carries the lender's own disclosures. The real gap: no owner-occupancy slot, so certified consumer fragments (home-solicitation cancel, TILA) can be spoken to a business buyer.
EXISTING ELEMENTS: R153 usage-authorization from account holder, mismatch routing; R61 savings only from verified data; R72 calculator_output + substantiation id; R60 lender decisions; R17 lender disclosures in e-sign packet; R71 suitability table.
NEW HARDENING: NEW: (1) An owner_occupied slot: one QUALIFY question, cross-checked against county homestead-exemption and mailing-address records; disagreement -> clarify, then human. (2) Not owner-occupied -> NOT_SUITABLE for the consumer product row; honest exit with referral to a human commercial desk. (3) A savings fragment requires bill_payer == a signing record owner, else no figure. (4) An invariant: consumer-credit and home-solicitation fragments are reachable only with owner_occupied verified.

## A7
DEFENSE: A whole-roof system priced on one unit's usage is blocked twice. R154: "the calculator must use the customer's exact tariff schedule ... on verified interval data, else no figure", and R29's calculator returns "insufficient-inputs -> no figure, offer survey". R43 adds per-slot ranges and cross-slot consistency checks that route to clarify. R156 makes the contract contingent on a survey-confirmed price, adds main-panel slots, and makes any change (a second service, a different interconnection) a new quote hash with re-disclosure, fresh e-sign and no-penalty exit. The gap: nothing compares the system size to the authorized meter, and unit and meter counts aren't slots.
EXISTING ELEMENTS: R154 exact tariff on verified interval data else no figure; R29 calculator insufficient-inputs; R43 cross-slot consistency checks; R153 verified_usage writer allowlist; R156 survey-contingent price + main-panel slot + change-order re-disclosure.
NEW HARDENING: NEW: (1) A unit_count slot from parcel use code plus one QUALIFY question; a meter_count / service-point list from the utility authorization API. (2) Sizing is capped to the authorized meter's verified usage; a system that would export beyond that meter's load needs a policy-table tariff row (e.g. virtual/aggregated net metering) or gets no figure. (3) More than one unit or meter -> lead-gen plus survey; no same-call price. (4) READ_BACK names the meter the system ties into.

## A8
DEFENSE: The design already ties the call to a specific address. The R73 challenge-response has the caller state name and address, matched against the record; R22 validates the address with the postal service and confirms the house number digit by digit. R79 makes the "roof/shade data lookup" an explicit calculator input, so "none" for a lake house under pines conflicts with aerial shade data, and R43 cross-slot consistency checks route the conflict to clarify. R156 makes the contract contingent on a survey-confirmed price with roof-structure slots, and blocks install, inside the cancellation window. The gap is real, though: QUALIFY questions and READ_BACK don't name the property, so the answers have no referent.
EXISTING ELEMENTS: R73 challenge-response incl. address; R22 postal validation + digit-wise house number; R79 roof/shade lookup as calculator input; R43 cross-slot consistency -> clarify; R156 survey-contingent contract; R82 explicit product read-back lint.
NEW HARDENING: NEW: (1) Every QUALIFY fragment carries the validated street slot ("the home on <street>"), and R82's lint adds the property street address to READ_BACK. (2) The caller's own stated address in IDENTITY must equal the lead property; if not, ask once "Are we talking about the home on <street>?", and a mismatch -> lead-gen. (3) Roof age cross-checked against permit records and shade against aerial lookup; any disagreement -> ROOF_FIRST.

## A9
DEFENSE: The residential figure never renders on an ag account. R154 requires "the customer's exact tariff schedule ... on verified interval data, else no figure", and the policy table carries only residential schedules, so an ag time-of-use tariff yields no figure. R43's per-slot ranges send out-of-range usage to clarify. R88's record-owner lookup returns a farm LLC, and R153 routes an account-holder mismatch with the record owner to the written-authorization path. R72 lets savings fill only with calculator_output plus a substantiation id, and the calculator can't produce one without a tariff row. R156 makes a ground mount a survey change order. The gap: the policy table has no explicit tariff-class key.
EXISTING ELEMENTS: R154 exact tariff else no figure; R43 per-slot ranges -> clarify; R88 record-owner lookup + capacity flags -> human review; R153 account-holder/record-owner mismatch routing; R72 substantiation-gated savings; R156 survey change orders.
NEW HARDENING: NEW: (1) A tariff_class key on every calculator row, read from the utility authorization API; any non-residential class (agricultural, commercial) -> NOT_SUITABLE for the residential product, honest exit with referral to a human commercial desk. (2) Entity record owners (LLC, partnership, corporation) -> no same-call close, human review. (3) Ground-mount siting is out_of_scope(product_request) with the R82 honest no-offer fragment.

## A10
DEFENSE: No stranger gets an SMS. R146: "never send a co-owner envelope to vendor-sourced contact data"; the verified customer gets a "co-signer required" packet and chooses the channel, or the co-owner self-opts in. So nothing is disclosed to the vendor-seller without the occupants' own choice. Nor is anything encumbered: R159 draws identity answers from public records and runs a phone-to-record-owner match, and the occupants aren't record owners, so the call is "lead-gen only". R120 blocks lien filing until every record owner is independently verified, and R88 sends capacity issues to human review. The gap: the system doesn't explain equitable vs. legal title, so occupants may act on the call.
EXISTING ELEMENTS: R146 co-signer packet, customer-chosen channel, no vendor-sourced contact; R159 public-records identity + phone-to-owner match -> lead-gen only; R120 no lien until all owners verified; R88 human review path; R156 cancellation-window contingency.
NEW HARDENING: NEW: (1) An OWNERSHIP_MISMATCH state: when the caller says they own the home but the record owner differs, one fixed question ("Is the home titled in your name?"), then an honest exit: no quote, no close, a written explanation that the titled owner must take part. (2) No contact with a record owner who isn't on the call unless the verified caller chooses it in writing. (3) A recorded land-contract memorandum or "contract for deed" lexicon -> NOT_SUITABLE with a note to check the contract for alteration or lien restrictions.
