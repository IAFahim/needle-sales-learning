
### Round 184. Winner: Breaker
- Topic: Batch-variant inference on the pinned Needle fleet makes certified near-tie decisions depend on how many other calls are in flight
- Attack: Caller says "yeah, I guess that's fine" at COMMIT. Replay at certification ran Needle alone (batch size 1): margin 0.031, just above the near-tie threshold, so affirm. In production at 6 pm the server batches this turn with 40 other calls; padding and different kernel tiling change reduction order, logits shift in the third decimal, the margin falls to 0.029, so clarify (or flips the other way and commits). Same weights hash, same build, same hardware class, so the certificate still claims it applies. The certificate keys on weights, build, hardware and tool list, not batch composition. Thinking Machines (Sept 2025) showed common inference kernels are not batch-invariant: identical inputs give different outputs depending on concurrent load. "Bit-identical replay" and every threshold-sized margin are then unreproducible. Source: thinkingmachines.ai "Defeating Nondeterminism in LLM Inference"; simonwillison.net/2025/Sep/11/defeating-nondeterminism.
- Defense: The scenario's commit never rests on Needle's margin. R87 makes the commit gate "lexical over final ASR tokens (independent of Needle output)", and R141 replaces yes/no with an action-production prompt ("please say 'send the contract'"). "Yeah, I guess that's fine" is a hedged, non-lexicon answer, so R77 sends it to a closed re-ask whatever the logits are. For non-commit near-ties, both sides of the threshold are safe: clarify is a re-ask. Still, batch variance does undermine "bit-identical replay" (R53), so we close it.
- Verdict: The commit example is blocked by existing parts: R87 makes the commit gate lexical, R144 asks for the action phrase "send the contract", and R77 sends hedged answers to a re-ask. But the attack is about the certificate and replay claims. R53 keys the certificate on weights, kernel build and hardware, and promises cross-node bit-identical replay. R135 re-keys runtimes on bitwise-identical margin decisions. Nothing in the design pins batch composition or uses batch-invariant kernels, so those reproducibility claims, the daily canary and the equivalence re-keying are not guaranteed under production co-batching. The Designer concedes this, and the remedy is entirely new.
- Fix: Run certified inference with batch-invariant kernels (fixed reduction order and split sizes), or at batch size 1 per pass. Put the batching policy in the certificate key. Add a release CI test that replays every gold set under random co-batched load at sizes 1..N and requires bitwise-identical tokens and margin decisions.

### Round 185. Winner: Designer
- Topic: The argument grounding gate is a presence check, so partial spans and truncated values pass ("150" is found inside "1500")
- Attack: Caller: "our bill runs about fifteen hundred in summer, one-fifty in winter." ITN gives "1500" and "150". Needle emits monthly_bill=150 for the summer question. Grounded. Another caller: "the roof is fifteen years old"; Needle emits roof_age=5 after a max-token cut or a dropped digit; "5" occurs inside "15", so grounded. A street "1234 Oakmont Ridge" truncated by the argument token limit to "1234 Oak" is also a substring. Every one passes the gate and lands in the slot store as spoken. "Found in the final ASR text" checks that a string exists, not that it is the whole span the caller meant. Prefixes, digit fragments and truncations of a real value are always "found". The gate catches invented values but blesses exactly the corrupted-real-value errors a 26M copier makes most.
- Defense: R61 does not use a substring search. It requires the value to be "found by deterministic extractor in the turn's final ASR span", and the R43 number normalizer yields whole numeric entities with unit and period tags, not character runs. Spoken bills "only fill coarse routing bands" (R72). Savings and sizing use only verified_usage (R153), never speech. Roof age is a qualification-critical slot, so it is read back and confirmed (R2). Street addresses are postal-validated, with the house number confirmed digit by digit (R22), and identity runs by challenge-response against the record (R73). So "1234 Oak" or a dropped digit is caught before anything depends on it.
- Verdict: R61 does not describe a substring search. It requires the value to be "found by deterministic extractor in the turn's final ASR span", and R43's normalizer produces whole numeric entities with unit and period tags. A fragment such as "5" from "15", or "150" applied to the summer period, therefore does not match. Existing layers also limit the damage: spoken bills only set coarse bands (R72), sizing and savings use only verified usage (R61/R72), roof age goes through critical-slot read-back (R2), and addresses are postal-validated with the house number confirmed digit by digit (R22).

### Round 186. Winner: Designer
- Topic: Grounding accepts the right string bound to the wrong role or under negation (argument swap and scope errors)
- Attack: QUALIFY asks roof age and move horizon. Caller: "Roof's not twenty, it's maybe eight, and we're here another twenty easy." Needle emits roof_age=20, move_horizon_years=8. Both numbers appear in the transcript, both pass grounding, suitability table says roof under 25 and horizon over 7: SUITABLE. The real answer (horizon 20, roof 8) also passes, but a negated "not twenty" and a swap between two numeric slots are invisible to a gate that only checks membership. Multi-number turns are common in discovery, and small seq2seq models are weakest at role binding and negation scope. Provenance says "spoken", so downstream guards treat a swapped value as caller fact. Suitability, sizing and the read-back then rest on a mis-bound number that no deterministic check can detect.
- Defense: The swap is exactly what R2's "deterministic critical-slot read-back" exists for. Roof age and move horizon are qualification slots (R71), so each is read back ("roof about twenty years, staying about eight more?") and confirmed before suitability uses it. Two independent errors are needed for harm. R44 adds a "summary read-back after multi-fact turns", and R43 cross-slot consistency checks route conflicts to clarify. A caller who just said "not twenty" will correct "twenty" on the read-back. The correction then goes through correct_fact (R52) and triggers a backtrack.
- Verdict: R2's critical-slot read-back names roof age, and R71 makes move horizon a qualification slot. A swapped pair is read back ("roof about twenty, staying about eight") before suitability uses it. R44 adds a summary read-back after multi-fact turns, and R52's correct_fact sends a correction back through the flow. Harm needs both a binding error and a caller who confirms the wrong read-back, which is the two-error structure R2 was built for.

### Round 187. Winner: Designer
- Topic: Constrained decoding masks are written in characters but Needle emits subword tokens, so some valid argument values are unreachable or forced into tokenizations Needle never saw
- Attack: The LOCAL grammar for monthly_bill allows digits only, emitted digit by digit. Needle's tokenizer normally writes "250" as one token, which the grammar masks to fit its per-character automaton, forcing "2","5","0", a non-canonical sequence absent from training. Probability mass collapses onto whichever single digit was most likely after "2"; the emitted value becomes "25" or "200". Similar boundary clashes hit enum names sharing prefixes ("battery" vs "battery_backup"). Token/grammar misalignment is a known constrained-decoding failure: masking at token boundaries forces non-canonical tokenizations and distorts outputs (Beurer-Kellner et al., "Guiding LLMs the Right Way", arXiv 2403.06988; "Lost in Space", arXiv 2502.14969). Certification on unconstrained eval data never sees this distortion.
- Defense: The premise that "certification on unconstrained eval data" is false. Under R2 and R121, certification counts only real calls in which Needle drove the transitions, so it measures the deployed constrained decoder, distortion included. R122 already made "each event name a single reserved vocabulary token", so names can't share prefixes. Numbers never become spoken facts: R43's normalizer and R61's grounding check every value. A forced "25" for "250" is not the extracted entity, so the turn goes to clarify. Bills only set coarse bands (R72).
- Verdict: Certification counts only real calls (R2), so it measures the constrained decoder as deployed, distortions included. The premise that it is certified on unconstrained data is wrong. R125 already makes each event name a single reserved token. A forced "25" for "250" is not an extracted entity, so R61 sends the turn to clarify, and bills only set bands (R72). The remaining effect is a higher clarify rate, which costs availability but causes no harm.

### Round 188. Winner: Designer
- Topic: Encoder context overflow: state tool schemas plus agent context plus a long caller turn exceed Needle's input window, and truncation silently cuts the caller's last words or the tail of the tool list
- Attack: At READ_BACK the LOCAL tool list (affirm, deny, clarify-per-term, dispute_prior_statement, out_of_scope, incomplete...) with JSON schemas takes most of the encoder window. Caller gives a 70-word answer ending "...so yes on the size, but not the loan, I'm paying cash." Tokenizer left-to-right truncation drops "but not the loan, I'm paying cash." Needle sees "...so yes on the size" and emits affirm with high confidence. No error is raised; the input simply fits after truncation. A 26M on-device model has a short fixed context; state-dependent tool lists vary input length by state. Nothing in the design measures or blocks truncation, and per-state certification on typical-length turns never exercises the overflow. The lost words are the ones that change meaning.
- Defense: A 70-word answer never reaches a commit. R81: "affirm must be a short direct answer turn (length/structure check in deterministic commit gate)". R86/R87: "conditional affirms ('yes, but ...') excluded from commit" by a lexical gate over the full final ASR tokens, which never see Needle's truncated input. Long turns also go through R44's "deterministic segmenter -> per-segment Needle -> merger", so "but not the loan, I'm paying cash" is its own segment. Long turns are a separate Tier A stratum, so overflow-length inputs are certified.
- Verdict: The example commit fails existing gates that never see Needle's input. R81 requires a short direct answer turn, R86 excludes conditional affirms, and R87 checks the full final ASR tokens lexically. Long turns already go through R44's segmenter, are handled per segment, and form their own Tier A stratum. GLOBAL's fixed ~8-tool list (R34) keeps the safety pass short. Nowhere does the design state an explicit window-fit check, but the harmful paths in the attack are already gated.

### Round 189. Winner: Breaker
- Topic: The "exactly one event" constraint collapses multi-intent turns, so logits decide which of two safety intents survives
- Attack: Caller: "Put me on your do-not-call list and let me speak to your supervisor about how you got my number." GLOBAL must output exactly one event. request_human edges out stop/DNC; the lexicon misses because the caller said "do-not-call list" inside a longer clause the dialect patterns don't anchor. The call warm-transfers a DNC requester to a sales supervisor. Another caller: "Cancel it, and who am I even talking to?" yields request_caller_identity; the cancel is never recorded. Real callers routinely bundle intents. A single-label schema has no way to say "both", so the lower-scored legal obligation is dropped by construction. TCPA/TSR DNC requests must be honored whatever else is asked; a forced single choice turns compliance into an argmax.
- Defense: DNC never depends on a GLOBAL argmax. R66: "mid-call stop = union of Needle GLOBAL + lexicon". The lexicon is a pattern match, not anchored to the whole utterance, and it includes "don't call / take me off / remove my number". R105 fires the stop check on stop-adjacent tokens ("list", "calling"). R44 splits bundled turns into segments, each classified separately. As a backstop, R66's "post-call DNC sweep of every transcript (lexicon + GLOBAL re-run) before any redial" catches any miss. R6 already canonicalizes sets by precedence, "safety/opt-out" first.
- Verdict: R63 constrains decoding to exactly one call, and the final plan repeats that for GLOBAL. So a bundled turn can only keep one safety intent. DNC is partly covered by the lexicon union (R66) and the post-call sweep before any redial. However, R24's Tier 1 list ("don't call", "take me off"...) does not clearly match "put me on your do-not-call list". R108's stop-adjacent check applies only to overlap residue during agent playback, and R44's segmenter covers long turns only. The cancel case has no backstop at all: cancel_or_rescind is a Needle-only GLOBAL event with no lexicon (R76), and the post-call sweep checks only DNC. "Cancel it, and who am I even talking to?" therefore loses the cancel by construction.
- Fix: Make GLOBAL multi-label: each safety event gets its own calibrated threshold and every event above it fires, handled in a fixed order (DNC write, then cancel, then identity/human answers; any transfer carries the DNC flag and is service-only). Add a cancel/rescind lexicon to the deterministic union, and extend the post-call sweep to cancel intents. Add "do-not-call" and "do not call list" to Tier 1, plus a bundled-intent Tier A stratum.

### Round 190. Winner: Designer
- Topic: GLOBAL and LOCAL are scored by separate softmaxes over different label sets, so a strong-but-sub-threshold safety signal is discarded while LOCAL commits
- Attack: At COMMIT: "Okay, yes, but honestly I want to run it past someone at your company first." GLOBAL: none 0.52, request_human 0.44; no near-tie rule fires across "none" vs a safety event, so none. LOCAL, seeing a short lexical "yes": affirm 0.91. Arbitration sees GLOBAL=none, LOCAL=affirm, and commits. The design compares top-1 vs top-2 within a pass but has no rule combining a 0.44 safety probability with a LOCAL commit. The two passes have no common probability scale and no joint decision rule. A commit should be blocked by substantial safety mass, yet the gate only reads each pass's argmax. Calibration of each pass separately says nothing about the joint error rate of "commit while a safety event was nearly chosen".
- Defense: This caller fails the commit gate on its own: "yes, but ..." is a conditional affirm, and R86 excludes it from commit. R141 requires the action phrase "send the contract", not "yes", and R87's gate is lexical, so LOCAL affirm=0.91 is never enough to commit. R130 calibrates both passes with temperature and prior correction, so their probabilities are on a meaningful common scale. R149's overcommitment and vulnerability signals also block a same-call close.
- Verdict: The example caller cannot commit under existing rules: "yes, but..." is excluded by R86, R144 requires the phrase "send the contract" rather than "yes", and R87's gate is lexical and short-answer only (R81). R133 calibrates both passes to target false-commit rates, and R152's overcommitment signals block a same-call close. A caller who says only "send the contract" is unlikely to carry heavy request_human mass. The lack of a formal joint rule is a refinement, not an open path to harm.

### Round 191. Winner: Designer
- Topic: Fragment wording variants change Needle's input distribution, but certification is keyed by fragment id, not by wording
- Attack: The read-back question has three approved wordings, chosen deterministically (e.g., by call hash). Needle's input includes the agent's last utterance to interpret "yes". Wording 1 ends "Shall we go ahead?"; wording 3 ends "Any questions before we go ahead?" The caller says "No, go ahead." Under wording 3 "no" answers the questions clause; Needle learned "no"-first strongly as deny. Wording 3's traffic shows a different commit/deny confusion matrix, but the per-fragment-id certificate pools all three. If Needle doesn't see the question, a bare "yes" is ungroundable; if it does, every wording is a distinct input distribution. Rule-of-three per state on pooled traffic hides a variant with several times the error rate, and adding a new wording silently changes classifier behaviour without touching weights.
- Defense: "No, go ahead" cannot commit. R141 made the commit question an action-production prompt, and R87's lexical gate needs "send the contract". A polarity-mixed answer is R77's ambiguous_polarity, which leads to a closed binary re-ask. R38: "confirmation prompts contain no answer words." R148's leading-question lint covers every state. The R113 render log already records the wording id per call, so per-wording error rates are measurable today.
- Verdict: The premise fails on the design itself. Needle maps "one utterance + the current state's tool schema" (Runtime section), and affirm/deny carry the target question id deterministically (R58), so the agent's wording is not part of Needle's input. "No, go ahead" cannot commit anyway: R144's action phrase, R87's lexical gate, R77's ambiguous_polarity re-ask and R38's no-answer-words rule all stop it. R59 chooses wordings deterministically and logs them, so production traffic has the same wording mix as the certified traffic. R116's render log records the wording id, so per-wording rates can already be measured.

### Round 192. Winner: Designer
- Topic: Hierarchical statechart precedence: a substate that handles the same event shadows the root GLOBAL exit
- Attack: In WAITING_FOR_SIGNATURE, designers add a local handler for cancel_or_rescind meaning "cancel and resend the envelope" (caller: "cancel that text, send it to my other phone"). The caller later says "cancel the whole thing." StateSmith, following UML semantics, gives the innermost state first claim on the event; the local handler consumes it, resends the envelope, and the root cancel_or_rescind exit never runs. The model check passes because the root transition exists and is reachable from other states. In hierarchical machines an event handled by a child stops propagating to parents (UML run-to-completion, child-first). "GLOBAL exits from any state" is only true where no substate reuses the event name. The invariant checks existence of a root edge, not that every state actually reaches it for every GLOBAL event.
- Defense: The checker already works on the right artifact. R131 enumerates "the compiled binary's (state, event, abstract-guard) transition relation by harness" and diffs it against the graph. The relation includes child-first resolution, so (WAITING_FOR_SIGNATURE, cancel_or_rescind) mapping to resend shows up there. R76's cancel_or_rescind exits to CANCEL with no persuasion. R60 already gives envelope help its own events ("help_with_screen offers resend/wait/callback only"), so "cancel that text" was never meant to be cancel_or_rescind.
- Verdict: The final plan states "GLOBAL exits from any state" as a model-checked invariant over the exported graph. The attack's claim that this checks only whether a root edge exists is an assumption, not a fact stated in the design. R134 already enumerates the compiled binary's effective (state, event) relation, which follows child-first resolution, so a shadowed pair would appear in the artifact the checker uses. R60 already gives envelope help its own events (help_with_screen: resend/wait/callback), so the design never needed to reuse cancel_or_rescind locally. The risk is real enough that the check should be spelled out.

### Round 193. Winner: Breaker
- Topic: StateSmith machines are single-threaded run-to-completion code with no event queue, so concurrent event sources are serialized by hand-written glue outside the model check
- Attack: A Needle turn dispatches affirm into COMMIT; during its entry action (outbox write, fragment selection) the e-sign vendor webhook, a WAITING_FOR timeout tick and a telephony hangup arrive on other threads. Glue code calls dispatch() from the webhook thread while the first dispatch is mid-transition. Current-state variable and slot store interleave: the machine records CONTRACT_SENT, then the hangup handler exits to WRAP_UP, then the stale webhook moves it to SALE_PENDING after the call ended. StateSmith generates plain C with a dispatch function and no built-in queue, locking or re-entrancy protection; concurrency, ordering and timers are the integrator's job. The model checker verifies the graph assuming atomic, ordered events, so every race lives in uncertified code the invariants never covered.
- Defense: The existing design already serializes effects. Actions only append intents to the outbox, which drains only on committed turns (R13). Batches are transactions on a staged store (R6). Webhooks are only "a wake-up hint" with pulled status, and with "monotonic status" (R133). Hangup is a root telephony event (R35). The R131 runtime trace monitor refuses commit effects without READ_BACK on the trace. A post-hangup move to SALE_PENDING driven by a genuinely pulled "completed" status is also correct: callers may sign after the call. The real gap is glue re-entrancy.
- Verdict: The existing parts serialize effects and harden webhooks. R13 only lets effects leave through the outbox on committed turns. R136 treats a webhook as a wake-up hint with pulled, monotonic status. R134's trace monitor guards commit effects. None of these says who calls dispatch() or from which thread. StateSmith generates plain dispatch code with no queue or re-entrancy protection, so Needle results, webhooks, WAITING_FOR timers (R55) and telephony events (R35) can interleave on the current-state variable and the slot store, outside anything the graph checker verifies. The Designer concedes the "glue re-entrancy" gap, and the fix is new.
- Fix: Use a single-writer actor per session. All event sources enqueue into one FIFO mailbox, drained by one thread that calls dispatch() run-to-completion. dispatch asserts non-reentrancy and fails closed. Events carry a session epoch, and stale ones are dropped. Model-check the mailbox glue over all interleavings (e.g. TLA+), and add random-interleaving fault injection that must yield only legal traces.
