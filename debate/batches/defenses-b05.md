## A1
DEFENSE: A bare "Yes" cannot close on its own. R15 requires a "Teach-back before close (customer states payment+term; code compares)": she has to say the payment and the term in her own words. A listening-"yes" can't produce those. Even after COMMIT, CONTRACT_SENT only sends a written state-specific contract with a cancellation notice (R17). Signature is a separate OTP-gated e-sign act (R22), and install waits out "Longest statutory cancellation window ... for all" (R15). A contract signed under that misunderstanding gets rescinded, and that fails the success label (R71). That's the point where this pragmatic failure would show up and get counted.
EXISTING ELEMENTS: R15 teach-back, R15 longest cancellation window for all, R17 close pipeline, R22 OTP-gated envelope, R71 success label + sampled suitability audit, R77 narrow affirm set.
NEW HARDENING: The commit question becomes an action-production prompt ("To have the contract sent, please say 'send the contract'"), not a yes/no. A run of 3+ consecutive bare-affirm turns forces a delayed teach-back after an intervening topic. Suitability audit labels add "consent understood" (asked in a human post-sign check on the sampled calls).

## A2
DEFENSE: "I will consider it" books nothing. Under R41, the agent "proposes concrete times and books only the confirmed one". With no confirmed time there's no callback. R21 sets a refusal budget ("max one approved acknowledge-and-ask") and an invariant of "no pitch after decline". R15's defers_decision(to) feeds the vulnerability counter, and NO_SALE_SAFE_EXIT suppresses redial. The real gap is that indirect refusal isn't labeled as decline, so I'm closing it.
EXISTING ELEMENTS: R41 confirmed-time-only booking, R21 refusal budget + no-pitch-after-decline invariant, R15 defers_decision + NO_SALE_SAFE_EXIT + redial suppression, R24 single check question, pre-dial frequency caps.
NEW HARDENING: indirect_decline label class ("may be difficult", "I'll consider it", "I'll think about it" with no time), trained from a high-context-refusal red-team stratum and treated as decline. The response is one fixed closed question: "Would you prefer we don't call again?" Anything but an explicit time request means suppress. A second non-committal defer on any later contact closes the lead and writes internal DNC. The post-call sweep gets the same lexicon.

## A3
DEFENSE: Speech already avoids names and honorifics. R62 makes "name-free fragment variants by default", so nobody gets greeted "Mr." or has given and family names swapped. Name changes are "confirmed in writing". Identity isn't checked on the name alone: R88 looks up record owners "on validated address", and R73 challenge-response takes name and address together. R46's matched-pair tests already track "path-divergence" as a Tier A metric. The real gap is exact-string matching on name tokens.
EXISTING ELEMENTS: R62 name-free fragments + written name confirmation, R73 challenge-response, R88 record-owner lookup, R46 prohibited-basis tags + matched-pair tests, WRONG_PARTY state.
NEW HARDENING: The name matcher becomes a token-set match across lead and county records: any order, compound surnames, particles and hyphens normalized, romanization variants. If the address matches and any surname token matches, the result is VERIFIED. A partial match goes to clarify/human, never to the WRONG_PARTY drop. A lint bans all honorific slots. False-WRONG_PARTY rate is a release-blocking matched-pair stratum over synthetic name structures (not inferred ethnicity).

## A4
DEFENSE: Some of this is already covered. The R25 incomplete() label and the dangling-word rule stretch endpointing to 2-3s, and Tier A states wait longer. R56 request_human is available in every state. Fallback is "callback or human", and R42 RELAY_MODE already has a Tier A accessibility metric. R98's media detector looks for far-field speech (low direct-to-reverberant ratio, a music bed), and a near-field electrolarynx doesn't fit that. Still, the attacker is right that there's no disability stratum and a callback can loop, so both get fixed.
EXISTING ELEMENTS: R25 semantic endpointing, R56 request_human, deterministic fallback (callback or human), R42 RELAY_MODE accessibility metric, R98 far-field criteria, R26 per-group bounds.
NEW HARDENING: Speech-disability strata (dysarthria, stammer, aphasia, electrolarynx) get per-group release-blocking bounds. A number that hit an unintelligible fallback is routed only to a human on its next contact, never back to the automated path. An extended-timing profile (longer timers, no speculation) turns on after the first unintelligible turn. Electrolarynx audio goes into training as a near-field negative for media.

## A5
DEFENSE: A solar loan gives the son no cash. The lender runs the application and decides, and the money goes to the installer, so this pattern's payoff is small. Existing layers still apply. R9 speaker_change resets identity, and side_talk is a labeled event. R88 sends capacity flags (POA, conservatorship) to human review. R15 has a delayed teach-back. Everyone gets the senior 5-day cancel window before install, and anti-phishing lines are in the preamble. I accept that a transcript can't show whispered duress.
EXISTING ELEMENTS: R9 speaker_change, side_talk event, R88 capacity flags -> human review, R15 teach-back + cancellation window, R89 anti-phishing fragment, R71 sampled suitability audit.
NEW HARDENING: Any side_talk or second-voice detection (diarization) during QUALIFY/READ_BACK/COMMIT means no close on this call; it routes to a human consult. For owners 65+, a human does an owner-only confirmation call after signing and before install ("Is anyone else asking you to do this?"). The written notice includes elder-exploitation resources.

## A6
DEFENSE: Signing by every record owner (R88) is legally necessary and protects owners. Whose contact gets used is a separate decision, and the design already treats outbound contact as gated: R74 says "no Needle tool can create outbound contacts" and has a per-number consent gate. R88's "co-owner notice before read-back" is the moment she'd raise the problem, and sensitive_event(distress) exits with no pitch. Still, sending an SMS envelope to a vendor-sourced co-owner number is a real gap.
EXISTING ELEMENTS: R88 signer list + co-owner notice before read-back, R74 per-number consent gate, R22 SMS only to dialed number, R19 sensitive_event, R88 human review path.
NEW HARDENING: The consent gate covers every outbound SMS/email, not only dials. A co-owner envelope is never sent to vendor data. The verified customer gets a "co-signer required" packet and chooses the channel, or the co-owner initiates via self-opt-in link. A new sensitive_event subtype, household_safety ("separated", "he can't know"), means no co-owner contact, no close, and a human-review path with confidentiality.

## A7
DEFENSE: "Two months behind on the mortgage" is a sensitive_event (R19): "type ∈ ... financial_hardship" with a deterministic lexicon pre-emption and a "no pitch on hardship" scripted exit. It doesn't need a suitability column because it's GLOBAL in every state. Savings come only from verified usage (R61). The dealer fee is in the finance charge (R32), the lender decides credit, and unsuitable closes are Tier A harm (R71). Affordability itself isn't yet a table row, though.
EXISTING ELEMENTS: R19 sensitive_event(financial_hardship) + lexicon, R61 verified-usage savings, R32 dealer fee disclosure, R71 suitability table + Tier A unsuitable close, compliance regulation profiles.
NEW HARDENING: The hardship lexicon gets explicit rows (behind on mortgage/rent, foreclosure, collections, shutoff notice) plus a red-team stratum. A suitability row requires the financed payment to be ≤ the calculator-verified savings band, or else it's NOT_SUITABLE/cash-only. PACE products are excluded or follow ability-to-repay per the regulation profile.

## A8
DEFENSE: Early yeses get no commit credit. R27 says "Commit tools exist only in post-read-back states; early affirmatives map to permission_to_continue." Every fragment is human-approved, compliance-signed and linted (R18), and the close needs R15's teach-back, where the customer produces the payment and term, which a habituated "yes" can't do. Wording variants are "chosen deterministically" (R59), not by a conversion-maximizing bandit. Success includes a suitability audit and survival of the cancellation window. Still, the opener-only ban is too narrow.
EXISTING ELEMENTS: R27 commit-only-post-read-back, R18 claims lint + compliance sign-off + net-impression open item, R15 teach-back, R59 deterministic wording choice, R65 yes-eliciting opener lint, R71 success label.
NEW HARDENING: The leading-question lint applies to every state: it bans tag questions ("right?", "don't you?", "wouldn't you agree") and value-laden yes-questions. Discovery fragments must be open or neutral-choice. A whole-path CI check caps the expected-affirm count before READ_BACK. Variant selection is never optimized on conversion.

## A9
DEFENSE: "Biggest system" is impossible. Sizing comes only from calculator_output on verified usage (R61, R72), so stated wants can't enlarge the contract. Barge-in during mandatory read-back segments replays the segment from the start (R39), so interrupting can't skip READ_BACK. R15's teach-back requires stating payment and term. Install waits out the cancellation window for everyone, and the lender runs the application. Enthusiasm isn't a vulnerability signal yet, though.
EXISTING ELEMENTS: R61/R72 calculator-only sizing, R39 mandatory-segment replay, R85 READ_BACK invariant, R15 teach-back + cancellation window, R88 capacity flags, R71 suitability audit.
NEW HARDENING: An overcommitment signal set feeds the vulnerability counter: requests above the calculated size, "sign me up" before a quote, repeated barge-in during the read-back, and pressured speech rate (a deterministic prosody feature). Above a threshold there's no same-call close; the case goes to a written proposal plus a human consult after a cooling-off period. High-value contracts get a human confirmation call before install.

## A10
DEFENSE: The agent can't be a companion. The AI designation is in the unskippable preamble (R31). R94's persona-truth lint bans first-person life claims ("family", "I live"), so it can't share grandchildren stories. R69's call budget counters (total turns, per-state visits, wall-clock) force WRAP_UP. Suitability rows, verified-usage savings and the cancellation window all apply. Rapport as a buying motive is a real gap.
EXISTING ELEMENTS: R31 PREAMBLE AI designation, R94 persona-truth lint, R69 budget counters -> WRAP_UP, R63 small_talk internal transition, R15 cancellation window, R71 suitability audit.
NEW HARDENING: small_talk gets its own budget (≤2 replies per call) and icebreakers can't be re-entered after DISCOVERY. A high small_talk ratio means no same-call close and a written proposal with cooling-off. A lint bans flattery and rapport fragments ("so nice talking with you"). A fixed fragment before READ_BACK says: "There's no need to decide today."
