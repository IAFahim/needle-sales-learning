## A1
DEFENSE: A hallucinated "yeah" can only send an envelope. It cannot bind anyone. CONTRACT_SENT -> WAITING_FOR_SIGNATURE sends the e-sign envelope "by SMS with OTP, to all record owners + lender signers", and the sale exists only when the vendor webhook reports a signature (R60). Install also waits out the longest cancellation window. Before the commit question, R15's teach-back has the customer state payment and term, and code compares them. A cough cannot produce that. The ASR-confidence/no-speech pre-gate and the self-echo filter run first. The real gap is that the commit gate checks the shape of speech but not that speech happened.
EXISTING ELEMENTS: COMMIT gate (lexical affirm to read-back question id); ASR-confidence/no-speech pre-gate; R15 teach-back before close; R17/R60 CONTRACT_SENT -> WAITING_FOR_SIGNATURE, status only from vendor webhooks; e-sign OTP (R22); install waits for cancellation window; self-echo filter (R38).
NEW HARDENING: NEW, a voicing-evidence gate on commit. Every token in the commit set must line up, by ASR word timestamps, with frames that a pinned VAD and voicing detector score as near-field speech above a threshold. If they do not, the gate gives unintelligible plus a closed re-ask. NEW red-team stratum: non-speech audio (breaths, coughs, TV, line noise) played at AWAIT_CONFIRM. The certified false-commit rate on that stratum counts as Tier A.

## A2
DEFENSE: The binding terms do not depend on audio. Under R17 the escalator, rate and cancellation terms arrive as a written, state-specific contract with the lender's disclosures, and nothing exists until it is signed. Fragments hold "no literal numbers". Every fact token is a policy-table key, and R59 already logs the "seeded voice/prosody variation, chosen deterministically" per fragment id. Certification uses "humans listening to audio", not text replays, so a misread escalator is a labeled harm in the gate. The attack is still right that the TTS engine and its normaliser are not hashed in the bundle.
EXISTING ELEMENTS: Bundle content-hash and pinning (R67/R68); facts as policy-table keys, no literal numbers (R91); R59 deterministic wording/prosody choice; human audio-labeled certification; R17 written contract + cancellation notice; daily golden-audio canary.
NEW HARDENING: NEW, the TTS engine, voice, normaliser config and seed are pinned inside the certified bundle. Each policy row carries an authored spoken form ("two point nine nine percent"), and code verbalises the value before TTS, so the vendor normaliser never sees symbols. NEW, every fact-bearing clip is pre-rendered at build time and stored with an audio hash. CI sends it through the pinned ASR and compares the result to the spoken form. Any audio diff decertifies the clip. NEW, the daily canary also compares the rendered output audio.

## A3
DEFENSE: R14 already blocks this scenario's timing. AWAIT_* states are entered "only when the question finishes playing", and confirmation prompts contain no answer words. A "yes" uttered while the caller still hears the cancellation clause comes before the commit question. Even with 400 ms delay it reaches the server while the question is still playing, so the "overlap" rule and the *_SPEAKING state (no commit tools) discard it. The commit gate then needs an affirm aimed at the read-back question id, and R15 teach-back must match. The written contract repeats the cancellation term. The attack does show that the overlap windows use the server clock.
EXISTING ELEMENTS: R14 *_SPEAKING states, AWAIT_* after question completes, transcript timestamps vs playback window; COMMIT gate question id; R39 playout marks; R15 teach-back; R17 written cancellation notice; senior 5-day cancel window for all.
NEW HARDENING: NEW, path delay is measured per call from RTCP RR/DLSR (and from the agent-echo lag the self-echo filter sees). The playback and overlap windows are extended by one-way delay plus a jitter margin. Answers inside that guard band count as overlap and get a closed re-ask. NEW lint: the commit question is a separate fragment that follows the last mandatory read-back segment after a fixed pause. Calls whose measured delay is above a cap go to callback for the close.

## A4
DEFENSE: R39 already defeats the scenario as written. "Barge-in during mandatory segment = acknowledge, then replay from segment start". A callee saying "Hello? ...Hello?" over the PREAMBLE is barge-in, so the segment is not flagged as delivered and is replayed. While the path stays one-way, the repeated hellos keep the disclosure flag unset. Budget counters then reach WRAP_UP, and the invariant "every path DIAL->QUALIFY/SALES passes DISCLOSED" blocks any pitch. A silent callee on a one-way path is the gap. Playout marks prove transmission, not receipt.
EXISTING ELEMENTS: R39 mandatory-disclosure flags + barge-in replay; R31 compiled unskippable PREAMBLE and DISCLOSED invariant; R69 budget counters -> WRAP_UP; repair_request (R48); telephony events at StateSmith root (R35).
NEW HARDENING: NEW, media-health is a root telephony event. RTCP receiver reports from the far end must show the agent's RTP arriving (packets received, loss under threshold) across each mandatory segment's time span before the playback engine writes the delivered flag. If no RR is received, or the line keeps repeating "hello?" (a new deterministic pattern), the agent enters MEDIA_FAULT, hangs up, and books a lawful callback that starts again from PREAMBLE. NEW fault-injection stratum: one-way RTP in every state.

## A5
DEFENSE: Even a clipped uplink burst during agent audio counts as barge-in. R10 says "stop speaking, discard, reprocess". The agent goes quiet, the half-duplex phone switches back to the caller, and a repeated "take me off your list" reaches the ASR. The preamble's compiled opt-out sentence and the R75 DTMF opt-out keys give a channel that echo suppression cannot gate. The stop lexicon plus GLOBAL then end the call within the R24 window. The remaining gap is the case where the barge-in is too weak to trigger.
EXISTING ELEMENTS: Barge-in handling (R10/R14); R24 Tier-2 check "Should I keep going, or would you rather I let you go?"; R75 preamble opt-out + DTMF opt-out keys; stop lexicon union GLOBAL; post-call DNC sweep (R66).
NEW HARDENING: NEW yield rule: any near-end energy burst during agent playback, even one the no-speech pre-gate rejects, stops playout and enters PAUSE ("Sorry, go ahead"). NEW, overlap residue that contains stop-adjacent tokens ("list", "calling", "off", "stop") triggers the R24 check question at once. The post-call sweep flags overlap-residue calls as suppress-pending until a human reviews them. NEW lint: maximum fragment duration, so callers rarely have to talk over the agent. NEW red-team stratum: half-duplex/AEC gating with simulated uplink clipping.

## A6
DEFENSE: The design already removes the latency the attack assumes. The PREAMBLE is a compiled, pre-rendered audio block, and no Needle inference sits between the end of the greeting and its first segment. Dialing is limited to PEWC and inbound/warm leads (R59), and AMD error rate is tracked (R35). The attack is right that no 2-second invariant or abandonment counter exists, and long human greetings can be misread as machines.
EXISTING ELEMENTS: OPENING waits for callee; machine_greeting(); R35 AMD + VOICEMAIL state + AMD error rate; compiled PREAMBLE (R31); R25 endpointing; regulation profiles (most restrictive wins); R59 dial-list limits.
NEW HARDENING: NEW regulation-profile invariant: the first PREAMBLE segment starts within 1.5 s of the end of the completed greeting (TSR 310.4(b)(1)(iv), FCC 64.1200(a)(7)), and this is measured per call. AMD may not delay past that deadline. An unresolved AMD result is treated as human. VOICEMAIL is entered only on a beep or a confirmed machine cue, never on greeting length alone. NEW per-campaign 30-day abandonment counter capped at 3%, with the safe-harbor recorded message on abandon. A breach halts dialing.

## A7
DEFENSE: A false rise never refuses anyone. The <rise> token only "excludes from commit" and sends the call to a closed binary re-ask. The worst case is a callback or human handoff (R56 request_human), never a lost customer or a false yes. Per-dialect error bounds are already release blockers (R26/R93), and time-on-fallback per close state is tracked (R28). The prosody front end is not certified as its own component, and that gap is real.
EXISTING ELEMENTS: R80 prosody <rise> token; closed binary re-ask; clarify once then fallback; R56 request_human; R26/R93 per-group bounds as release blockers; R28 time-on-fallback metric; R46 matched-pair path-divergence tests; DTMF out-of-band events (R75).
NEW HARDENING: NEW, the prosody detector gets its own certification, with false-rise rate bounds per pitch range, sex and uptalk-dialect stratum as release blockers. A harmonic-based tracker reports voicing confidence. When confidence is low, no <rise> token is emitted (abstain, not veto). The rise is measured against the caller's own F0 baseline from earlier turns. If statement turns show habitual rise, the feature is turned off for that call. NEW, after one failed closed re-ask the agent offers a DTMF confirm ("press 1 to send the contract"), still gated by teach-back and OTP signature.

## A8
DEFENSE: The vulnerability counter is semantic, not acoustic. R15 feeds it from Needle signals (confused(), wrong_party_reference(), defers_decision) plus unclear/contradictions. Slurred audio alone does not determine it. Fallback is "callback or human" (R56 warm transfer), not denial, and RELAY_MODE (R42) already treats accessibility as a Tier A metric. The design never meant fallback to count as success; only NOT_SUITABLE does. Still, speech disability is missing as a release stratum, and unintelligible counts can reach the counter.
EXISTING ELEMENTS: R15 vulnerability counter (semantic signals); R56 request_human; deterministic fallback (callback/human); R42 RELAY_MODE accessibility metric; R26 per-group bounds as release blockers; R46 path-divergence tests.
NEW HARDENING: NEW, speech-disability strata (dysarthria, hypophonia, stuttering, electrolarynx, aphasia) are added to gold sets, using consented data such as the Speech Accessibility Project. Per-group false-unintelligible and service-denial (fallback) rates are release blockers. NEW, unintelligible and low-ASR-confidence events are excluded from the vulnerability counter. NEW ACCESS_PATH: after repeated unintelligible re-asks, the agent offers DTMF answers, an SMS/web self-serve flow, or a human consultant with extra time. Exits on this path count as access failures, not successes, and get an ADA/Unruh review.

## A9
DEFENSE: A new voice cannot make the decision unnoticed. R9's speaker_change() "resets identity", so VERIFIED is lost, and personalized fragments and bookings are guarded by identity, owner and adult. A new party who speaks goes back through IDENTITY. The contract binds only after OTP e-signature by every record owner (R88), and a co-owner notice precedes the read-back. In California, NO_RETAIN is the default without affirmative retention consent (R40). Silent listeners remain the real gap, as does the missing replay of the disclosure.
EXISTING ELEMENTS: R9 speaker_change() resets identity; IDENTITY state; R88 record-owner signer list + co-owner notice; R40 NO_RETAIN in all-party jurisdictions; R31 PREAMBLE/DISCLOSED invariant; ask_if_human(); request_caller_identity.
NEW HARDENING: NEW, speaker_change() enters NEW_PARTY, which replays the compiled disclosure block (AI designation, company, purpose, recording, opt-out) as mandatory segments before any further pitch. The recording state reverts to NO_RETAIN until the new party consents. NEW, a short compiled re-disclosure ("reminder: I'm an AI assistant from <seller>, this call is recorded, say stop anytime") plays at the start of READ_BACK, which covers silent listeners. NEW, the commit gate requires the affirming speaker's diarization id to match the VERIFIED speaker.

## A10
DEFENSE: The sweep does not read the recording. It reads the live ASR transcript, which the pipeline already produces. A SIPREC fork failure therefore does not blind it. NO_RETAIN is "in-memory only" (R40), so the sweep runs at teardown on the in-memory transcript before it is purged. It keeps only a DNC flag, not content. The mid-call stop is the union of the lexicon and Needle GLOBAL, and DTMF opt-out still works. The attack's real point is the audit's selection bias.
EXISTING ELEMENTS: R66 post-call DNC sweep (lexicon + GLOBAL re-run); R40 NO_RETAIN in-memory mode; stop = lexicon union GLOBAL; R75 DTMF opt-out; R33 drift alarms; per-call harm budget.
NEW HARDENING: NEW: in NO_RETAIN calls, the teardown sweep is mandatory and runs before purge, with an attestation log; if the sweep fails, the number is suppressed. NEW: recording-fork health monitor; a missing recording or ASR transcript for any call → that number is not redialed until reviewed. NEW: NO_RETAIN calls form their own stratum run in a conservative profile: any unresolved unclear in the last turns or any Tier-2 stop → suppress redial. Harm is bounded by outcome proxies (later complaints, repeat DNC requests, rescissions) compared against the retained stratum, and the gate reports this coverage gap explicitly.
