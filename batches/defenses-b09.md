## A1
DEFENSE: The scenario's commit never rests on Needle's margin. R87 makes the commit gate "lexical over final ASR tokens (independent of Needle output)", and R141 replaces yes/no with an action-production prompt ("please say 'send the contract'"). "Yeah, I guess that's fine" is a hedged, non-lexicon answer, so R77 sends it to a closed re-ask whatever the logits are. For non-commit near-ties, both sides of the threshold are safe: clarify is a re-ask. Still, batch variance does undermine "bit-identical replay" (R53), so we close it.
EXISTING ELEMENTS: R87 lexical commit gate; R141 action-production commit prompt; R77 narrow unambiguous affirm set; R53 certificate keyed on runtime/kernel build, hardware class, pinned fleet, cross-node bit-identical replay; R132 equivalence-based re-keying; R139 admission control with Needle capacity tokens.
NEW HARDENING: NEW: certified inference runs batch-invariant kernels (fixed reduction order, fixed split sizes, as in the Thinking Machines recipe), or batch size 1 per pass, which is cheap for a 26M model. A release CI test replays every gold set with random co-batched load at sizes 1..N and requires bitwise-identical tokens and margin decisions. The batching policy is added to the certificate key.

## A2
DEFENSE: R61 does not use a substring search. It requires the value to be "found by deterministic extractor in the turn's final ASR span", and the R43 number normalizer yields whole numeric entities with unit and period tags, not character runs. Spoken bills "only fill coarse routing bands" (R72). Savings and sizing use only verified_usage (R153), never speech. Roof age is a qualification-critical slot, so it is read back and confirmed (R2). Street addresses are postal-validated, with the house number confirmed digit by digit (R22), and identity runs by challenge-response against the record (R73). So "1234 Oak" or a dropped digit is caught before anything depends on it.
EXISTING ELEMENTS: R61 argument grounding gate (deterministic extractor); R43 number normalizer, unit/period tags, ranges, cross-slot checks; R72 coarse bands; R153 verified_usage sole writer; R2 critical-slot read-back; R22 postal validation, digit-by-digit house number; R73 challenge-response.
NEW HARDENING: NEW: grounding means exact equality with one complete extracted entity, with token-boundary matching and no prefix or fragment matches. A turn with two candidate values for one slot (summer/winter) goes to clarify(slot) naming the period. Argument truncation at the token limit is a hard error that leads to clarify.

## A3
DEFENSE: The swap is exactly what R2's "deterministic critical-slot read-back" exists for. Roof age and move horizon are qualification slots (R71), so each is read back ("roof about twenty years, staying about eight more?") and confirmed before suitability uses it. Two independent errors are needed for harm. R44 adds a "summary read-back after multi-fact turns", and R43 cross-slot consistency checks route conflicts to clarify. A caller who just said "not twenty" will correct "twenty" on the read-back. The correction then goes through correct_fact (R52) and triggers a backtrack.
EXISTING ELEMENTS: R2 critical-slot read-back; R71 suitability slots; R44 summary read-back after multi-fact turns; R43 cross-slot consistency; R52 correct_fact GLOBAL backtrack; R26 Tier A numbers confirmed digit-wise.
NEW HARDENING: NEW: a deterministic role-binding cross-check. The extractor tags each number with its nearest slot cue ("roof", "here/stay/move") and with negation scope ("not X", "isn't X"). A negated value can't fill a slot, and a disagreement with Needle's binding sends the turn to clarify. QUALIFY fragments ask one numeric slot per question. A multi-number red-team stratum is added at Tier A.

## A4
DEFENSE: The premise that "certification on unconstrained eval data" is false. Under R2 and R121, certification counts only real calls in which Needle drove the transitions, so it measures the deployed constrained decoder, distortion included. R122 already made "each event name a single reserved vocabulary token", so names can't share prefixes. Numbers never become spoken facts: R43's normalizer and R61's grounding check every value. A forced "25" for "250" is not the extracted entity, so the turn goes to clarify. Bills only set coarse bands (R72).
EXISTING ELEMENTS: R121 Needle-driven certification; R2 real-traffic-only gate; R122 single reserved event tokens and pre-mask OOD score; R43 normalizer; R61 grounding gate; R72 coarse bands.
NEW HARDENING: NEW: (1) Argument masks are compiled over the tokenizer's vocabulary (a token-level automaton that allows every canonical tokenization), not per character. (2) Enum argument values become reserved single tokens, as event names already are. (3) Fine-tuning data is decoded through the same grammar, so training and serving match. (4) A CI property: for every value in each slot's range, the constrained decoder reproduces the canonical value from its gold input.

## A5
DEFENSE: A 70-word answer never reaches a commit. R81: "affirm must be a short direct answer turn (length/structure check in deterministic commit gate)". R86/R87: "conditional affirms ('yes, but ...') excluded from commit" by a lexical gate over the full final ASR tokens, which never see Needle's truncated input. Long turns also go through R44's "deterministic segmenter -> per-segment Needle -> merger", so "but not the loan, I'm paying cash" is its own segment. Long turns are a separate Tier A stratum, so overflow-length inputs are certified.
EXISTING ELEMENTS: R81 short direct-answer commit check; R86 conditional-affirm exclusion; R87 lexical commit gate over final ASR; R44 segmenter/merger and long-turn Tier A stratum; R34 fixed GLOBAL tool list keyed by hash.
NEW HARDENING: NEW: tokenizer truncation is disabled. A build check proves that, for every state, the tool-schema tokens plus the segmenter's maximum segment fit the encoder window, which sets the segment cap per state. At runtime an over-length input is an error that leads to re-segmentation, then clarify, and is never silently cut. Truncation events are logged as a drift signal.

## A6
DEFENSE: DNC never depends on a GLOBAL argmax. R66: "mid-call stop = union of Needle GLOBAL + lexicon". The lexicon is a pattern match, not anchored to the whole utterance, and it includes "don't call / take me off / remove my number". R105 fires the stop check on stop-adjacent tokens ("list", "calling"). R44 splits bundled turns into segments, each classified separately. As a backstop, R66's "post-call DNC sweep of every transcript (lexicon + GLOBAL re-run) before any redial" catches any miss. R6 already canonicalizes sets by precedence, "safety/opt-out" first.
EXISTING ELEMENTS: R66 union stop and post-call sweep; R93 dialect patterns; R105 stop-adjacent token check; R44 per-segment Needle; R6 precedence canonicalization; R24 Tier 1 stop list; R76 cancel_or_rescind GLOBAL.
NEW HARDENING: NEW: GLOBAL becomes multi-label. Each safety event is scored on its own calibrated threshold, and every event over its threshold fires. Fixed precedence handles them together: DNC is written first, cancel is processed, and then request_human or identity is answered (the transfer carries a DNC flag and is a service transfer, never sales). "do-not-call list" is added to the lexicon explicitly, plus a bundled-intent Tier A stratum.

## A7
DEFENSE: This caller fails the commit gate on its own: "yes, but ..." is a conditional affirm, and R86 excludes it from commit. R141 requires the action phrase "send the contract", not "yes", and R87's gate is lexical, so LOCAL affirm=0.91 is never enough to commit. R130 calibrates both passes with temperature and prior correction, so their probabilities are on a meaningful common scale. R149's overcommitment and vulnerability signals also block a same-call close.
EXISTING ELEMENTS: R86 conditional affirms excluded; R141 action-production prompt; R87 lexical commit gate; R130 per-release calibration of margin/OOD thresholds to target false-commit rates; R122 pre-mask OOD mass; R56 request_human.
NEW HARDENING: NEW: a joint safety-mass veto. In any commit-capable state, if the calibrated probability of any GLOBAL safety event exceeds a low veto threshold (set on the calibration split, far below argmax), there's no commit. The machine asks one closed question about that event ("Would you like to speak with someone at our company first?"). "Commit while safety mass > threshold" is certified as its own Tier A joint metric.

## A8

A polarity-mixed answer is R77's ambiguous_polarity, which leads to a closed binary re-ask. R38: "confirmation prompts contain no answer words." R148's leading-question lint covers every state. The R113 render log already records the wording id per call, so per-wording error rates are measurable today.
EXISTING ELEMENTS: R141 action-production commit prompt; R87 lexical gate; R77 ambiguous_polarity; R38 no answer words in prompts; R148 leading-question lint; R59 deterministic wording choice, logged; R113 render log with wording id.
NEW HARDENING: NEW: (1) The certificate key for every fragment that precedes an AWAIT_* state becomes (fragment id, wording id). (2) A lint bans compound or multi-clause questions in AWAIT fragments ("Any questions before we go ahead?" fails), so a "no" has exactly one target.

## A10
DEFENSE: The existing design already serializes effects. Actions only append intents to the outbox, which drains only on committed turns (R13). Batches are transactions on a staged store (R6). Webhooks are only "a wake-up hint" with pulled status, and with "monotonic status" (R133). Hangup is a root telephony event (R35). The R131 runtime trace monitor refuses commit effects without READ_BACK on the trace. A post-hangup move to SALE_PENDING driven by a genuinely pulled "completed" status is also correct: callers may sign after the call. The real gap is glue re-entrancy.
EXISTING ELEMENTS: R13 outbox; R6 staged transactions; R133 webhook-as-hint, pulled monotonic status; R35 telephony events; R55 WAITING_FOR timers; R30 checkpoints; R131 runtime trace monitor.
NEW HARDENING: NEW: a single-writer actor per session. Every source (Needle results, webhooks, timers, telephony) enqueues into one FIFO mailbox, drained by one thread calling dispatch() run-to-completion. dispatch asserts non-reentrancy and fails closed. Events carry a session epoch, and stale ones are dropped. The mailbox glue is model-checked (TLA+) over all interleavings. Random-interleaving fault injection must yield only legal traces.
