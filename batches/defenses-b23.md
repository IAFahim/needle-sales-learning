## A1
DEFENSE: The transfer is not a sink. R56 already tracks "human-request rate and post-request conversion", R28 tracks "time-on-fallback per close state", and R36 retires the big model only if "fallback rate < X%" and "A/B handoff lift < Y", so tuning that dumps hard calls into transfers fails promotion. Outcome labels are joined by session id (R50) from independent feeds (R163) and complaints link to the originating sales branch (R221), so a bad human close still lands on the bot's branch. R203: closers work only in a recorded company softphone/CRM, and flagged callers go to a non-commissioned reviewer. R169: unintelligible-fallback calls book nothing. The real gap: the 1e-5 trace stopped at the transfer.
EXISTING ELEMENTS: R56; R28; R36 retirement rule; R50 delayed labels by session id; R163 independent outcome feeds; R221 complaint linked to originating branch; R203 recorded softphone and non-commissioned routing; R169
NEW HARDENING: NEW: The audited "whole call trace" is the whole session, transferred leg included (recorded per R203). Human-leg harm counts in the originating state's Tier A budget. The per-state fallback/transfer rate is capped as a release blocker, so lowering the clarify threshold to shed hard calls fails certification.

## A2
DEFENSE: Leaving the counter out of the handoff is deliberate. R203's "allowlisted handoff schema ... never carries the vulnerability counter ... Those flags only change routing, to a non-commissioned reviewer", so a flagged caller never reaches a commissioned closer. Senior cancel needs no age flag: R15 gives the "Longest statutory cancellation window (CA 65+ 5 business days) for all". Paperwork can't skip READ_BACK. R134's independent outbox monitor "refuses CONTRACT_SENT ... unless the committed trace contains READ_BACK with a playback-engine completion mark for the same quote hash". R141 mails a contract summary with cancel instructions to every record owner, and R148 adds a human owner-only call before install for owners 65+.
EXISTING ELEMENTS: R203 handoff schema; R198 typed handoff (verification_strength); R15 longest window for all; R134 outbox trace monitor; R17 e-sign packet with cancellation notice; R141 mailed notice; R148; R152 cooling-off
NEW HARDENING: NEW: A human cannot commit by voice. A close after a transfer must hand the call back to the compiled READ_BACK and COMMIT states. A barge-in-cut READ_BACK restarts from segment start (R39). Any nonzero vulnerability counter on the handoff sets no_same_call_close.

## A3
DEFENSE: The example fails existing lints. "Eliminated their bill" is a banned "zero bill" claim under R18, and the quantifier "Many" needs a table key under R199. R92 permits only audited aggregate facts. Whole-call review exists: R18 includes a "claims audit in certification", the gate is measured "on whole audited call traces", and R124's Needle-driven canary has "100% human audit", so humans hear full rendered calls before wide release. R29 lints the rendered reply, and R32 runs the Reg Z co-occurrence lint across the whole reply, not per fragment. R151's whole-path CI check already reasons over sequences. One gap is real: R18 lists the "whole-path net impression audit" as open.
EXISTING ELEMENTS: R18 banned-claims lint and claims audit; R199 quantifier lint; R92; R29 runtime lint; R32; R91 whole-call CI property; R151 whole-path check; R124 canary 100% audit
NEW HARDENING: NEW: (1) A juxtaposition lint. Social-proof fragments may not appear in the same turn as, or within N fragments of, any personalized price or savings fragment. (2) A per-state "path book" of rendered bounded-length fragment sequences, coverage-sampled, which counsel signs for net impression. (3) "Net impression misleading" becomes an audit label.

## A4
DEFENSE: The instrument is guarded. R200's "planted gold calls ... mixed blind into every labeler's queue" gate whether a labeler's labels count, so churn-driven quality loss is caught and those labels are dropped retroactively. R131 measures inter-rater agreement and corrects estimates with the confusion matrix. Exposure is already cut down. R143 gives labelers "only the clipped turns under audit", not full calls. R119 redacts medical sensitive_event spans "from every retained transcript, audit sample". Sensitive exits are scripted fragments, so correctness is mostly readable from the R116 render log. The real gap: no welfare or exposure limits.
EXISTING ELEMENTS: R200 planted gold calls and concentration caps; R131 agreement and correction; R143 enclave and clipped turns; R119 health-data quarantine; R116 render log
NEW HARDENING: NEW: (1) sensitive_event, threat and distress clips go to a small specialist pool, transcript-first, with audio only when needed. (2) That pool gets daily exposure caps, rotation, opt-out without penalty, paid counseling and vendor contract terms. (3) Labeler tenure and gold accuracy per release are reported, and a shift in either blocks certification.

## A5
DEFENSE: Nobody is asked. R132 says affected Tier A states "revert automatically to deterministic fallback until the surge clears". R66 makes "budget breach -> rollback to previous certified artifact" automatic. R142's admission control already gates dials by system state. The noise problem is handled statistically: R126 sets a "family-wise alpha" across state × stratum tests, and R132 uses CUSUM, so the false-alarm rate is designed rather than tuned by hand. Calibration (R133) resets thresholds per release on audited data. The gap: the design never forbids snoozing or override.
EXISTING ELEMENTS: R132 automatic revert and audit surge; R66 automatic rollback; R126 family-wise alpha; R133 calibration; R142 admission control; R140 compatible rollback targets
NEW HARDENING: NEW: (1) Alarm thresholds and snooze settings are part of the content-hashed certified bundle, so changing one is a release with two-person compliance sign-off. (2) Tier A reverts have no runtime override. The campaign owner role has no permission, and the dial permit simply refuses. (3) Re-enabling a state requires the surge audit to pass, and every pause is logged.

## A6
DEFENSE: The premise is wrong about ownership. R71 makes the suitability table "versioned compliance-owned", not sales-owned. A changed row decertifies every branch that cites it (design §Runtime, R3). R140 makes the table "forward-only". R163 requires "decouple ops and installer bonuses from training labels". Suitability harm is checked immediately: R71 counts an "unsuitable close" as Tier A harm and requires "passes sampled suitability audit", and R211 cross-checks roof age against permit records and shade against aerial lookups. R150 requires payment ≤ verified savings. Gap: a loosened row is judged against itself.
EXISTING ELEMENTS: R71 compliance-owned suitability table and Tier A unsuitable close; certificate expiry on row change; R140 forward-only table; R163 bonus decoupling; R211 permit and aerial cross-check; R150; R199 two-person approval pattern
NEW HARDENING: NEW: (1) Suitability rows carry counsel-signed floors, and any loosening needs two-person compliance approval plus a written rationale. (2) The newly admitted cohort, homes that would have failed the old row, gets 100% suitability audit against an independent rubric, not the table itself. (3) It stays on a written-proposal path with no same-call close until delayed labels arrive.

## A7
DEFENSE: R203 requires "Closers work only in a recorded company softphone/CRM", with access logging and blocked bulk export. R198: "callbacks go only to the contact of record". R115's revocation ledger "is read at every dial (scheduled callbacks included)", and R138's linearizable permit, including the "pending_sweep" lock, is the single dial authority. R41 clamps callbacks to the lawful window. R170 makes every END write a writeback the permit reads. R202 makes the pre-visit confirmation a call to the number of record. The gap is enforcement on human devices and stale calendar entries.
EXISTING ELEMENTS: R203 company softphone; R198 contact-of-record callbacks; R115 revocation bus; R138 dial permit and pending_sweep; R41 lawful window; R170 writeback; R202
NEW HARDENING: NEW: (1) Reps never see the customer's number. The CRM offers click-to-dial only, through the softphone, which must win the R138 permit at dial time. (2) A booking is not a dial authorization. A DNC or sweep hit cancels linked calendar items through a WAITING_FOR substate. (3) Consult confirmations go by system SMS, not by rep calls. (4) Personal-device contact is a terminable offense, and a complaint naming an off-system call is Tier A.

## A8
DEFENSE: The design avoids the attack's own examples. "Senior" isn't encoded as an age slot: R15 applies the longest cancel window "for all". "Promptly" is concrete and lawyer-checkable: R31's invariant "every path DIAL->QUALIFY/SALES passes DISCLOSED", R165's ~6 s segment 1, and R109's "within about 1.5 s". Regulation profiles are policy-table rows with effective dates, and R222 already requires a "per-jurisdiction legal attestation field" on rows, a precedent for counsel signing row semantics. R70 checks invariants "across all profiles". R84 routes the unresolved AI-name question to counsel instead of letting an engineer choose. Gap: no signed guard-to-statute mapping, and "most restrictive" isn't a total order.
EXISTING ELEMENTS: R15; R31 invariant; R165; R109; R222 legal attestation field; R70; R84 open item for counsel; R134 binary-vs-graph diff
NEW HARDENING: NEW: (1) A traceability matrix. Every guard and invariant cites a statute row and carries counsel attestation over a generated plain-English rendering plus model-checker witness and counterexample call transcripts, which lawyers can read. (2) Combination is union of obligations and intersection of permissions, not ranking. A SAT check flags any unsatisfiable mix, and those jurisdictions go to lead-gen or a human.

## A9
DEFENSE: Labelers don't make legal calls; R79 says "policy is authored, only perception learned". Reg Z trigger terms are fixed at build time by the R32 co-occurrence lint on rendered replies. Claims are certified "by fragment id", and the R116 render log records exactly which fragments played. Counsel decides once per fragment and profile whether a string is lawful, and labelers judge facts such as what the caller said, which event applied and which fragment played. R221 gives "complaint" a "fixed policy definition ... applied blind". R200's planted known-answer calls, "including scripted harmful closes", gate labeler accuracy. R143 uses in-house or vetted staff. Gap: hedged-stop cases need jurisdictional judgment.
EXISTING ELEMENTS: R79; R32; fragment-id certification; R116 render log; R221; R200; R143; R24 Tier 2 stop handling; R189 multi-label GLOBAL
NEW HARDENING: NEW: (1) Labels are factual codebook fields. A counsel-authored decision table per regulation profile maps them to harm. (2) Codebook-ambiguous items escalate to an attorney panel. (3) An attorney-adjudicated random subsample measures labeler-to-counsel agreement each release and corrects the bound through the confusion matrix (the R131 method).

## A10
DEFENSE: The fallback is not humans improvising. R140 says that when no compatible bundle exists, "QUOTE/READ_BACK states drop to lead-gen or callback fallback", with no price and no terms. R169 says unintelligible fallback "books nothing". R47 issues contracts in registration states through "the registered salesperson of record". R134's outbox monitor blocks CONTRACT_SENT without the compiled READ_BACK, so no human can close on improvised terms. R142's admission control already stops new dials first when capacity drops, so the system cuts volume instead of overflowing. Gap: human fallback capacity and currency aren't gated.
EXISTING ELEMENTS: R140 lead-gen/callback fallback; R169; R47; R134 outbox monitor; R142 admission control; R56 staffed queue "if open", else booked consult; R203 recorded softphone
NEW HARDENING: NEW: (1) For states whose fallback is human, the dial permit also needs a reserved, trained-human capacity token, so expiries pause dialing instead of flooding humans. (2) Transfer agents must hold a current certification keyed to the live policy-table version and work from a StateSmith-driven script console. (3) A minimum monthly live volume keeps their skills current.
