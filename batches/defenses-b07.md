## A1
DEFENSE: The premise is wrong. R24 Tier 1 is a deterministic lexicon of "unambiguous, caller-directed" endings that explicitly includes "goodbye" and "not interested" and ends the call immediately. Stop = "union of deterministic lexicon ... and Needle GLOBAL", and the lexicon pre-empts Needle, so acknowledge never gets a chance. "I think I've heard enough" is also covered by R145 indirect_decline (lead suppressed unless the caller asks for a time). The post-call sweep re-runs the same lexicon. The real gap is narrower: the variant forms ("bye now", "gotta go", "I'm done") and the fact that Tier 1 hangs up without a polite closing.
EXISTING ELEMENTS: R24 Tier 1 stop lexicon ("goodbye"); stop = lexicon ∪ GLOBAL; R145 indirect_decline; R66 post-call sweep; R93 dialect patterns
NEW HARDENING: NEW leave_taking lexicon class plus a GLOBAL event for "bye/bye now/gotta go/heard enough/I'm done". It plays one fixed terminal fragment ("Thanks for your time, goodbye") and hangs up, with no question and no pitch. The lead is suppressed as an indirect_decline. Add a red-team stratum of pre-closing turns and a Tier A metric for talking past a goodbye.

## A2
DEFENSE: The loop case is already handled. R108's yield rule means any near-end burst stops playout and enters PAUSE ("Sorry, go ahead"), so the caller gets the turn at once. R107 handles a callee who keeps saying "hello?": that enters MEDIA_FAULT, which either replays the full PREAMBLE once the path is confirmed or books a lawful callback. R109 starts the first segment within ~1.5 s, so the 600 ms gap is bounded. R69 budget counters cap the call and go to WRAP_UP. Disclosures are never "skipped": the invariant "every path DIAL->QUALIFY/SALES passes DISCLOSED" means a call that runs out of budget never reaches a pitch. That fails safe and lawful, not silent. What's missing is a replay cap and a required segment order.
EXISTING ELEMENTS: R39 mandatory-segment playout marks; R108 yield rule/PAUSE; R107 MEDIA_FAULT; R109 1.5 s start invariant; R69 budget counters; R31 DISCLOSED invariant
NEW HARDENING: NEW ordered preamble: segment 1 (seller, sales purpose, AI) has a lint-enforced maximum of about 6 s. The remaining segments are short and chunked separately. Each segment may replay at most 2 times. After that the agent says "I'll let you go" and ends with no pitch. Add a per-segment interruption-rate metric.

## A3
DEFENSE: The legal basis is solid. The dialer requires a per-number PEWC artifact ("timestamp, seller, disclosure version", R74) captured by an independent consent-capture provider (R162). There is no vendor free text, so a fixed fragment can state system-sourced fields from that artifact: date and capture channel. A flat denial is exactly the kind of signal R115's revocation intake bus and R162's per-partner fraud metrics are built to consume. What's missing is an event that routes the question and denial to them. Today it falls into out_of_scope, which is safe (no false claim) but loses the record.
EXISTING ELEMENTS: R74 per-number PEWC artifact; R162 independent consent-capture provider + per-partner fraud metrics/auto-suspension; R115 revocation intake bus; R84 request_contact_info; R117 legal_threat/legal_hold; open item lead-vendor consent audit

## A4
DEFENSE: The attack misreads the schema. R63 defines the event as small_talk(valence), so a valence slot exists. The "Great to hear!" pick can only happen if a fragment ignores that slot. R153 already lints out flattery and rapport fragments, caps small_talk at ≤2, and forbids re-entering icebreakers. R151 requires discovery fragments to be "open or neutral". Real distress ("haven't slept", flood, sick kid) is a red-team target for R19 sensitive_event(distress / financial_hardship), and R150 adds hardship rows. What's missing is a build check that ties acknowledgment wording to valence.
EXISTING ELEMENTS: R63 small_talk(valence); R153 small_talk budget + flattery lint; R151 neutral discovery lint; R19 sensitive_event(distress); R150 hardship lexicon
NEW HARDENING: NEW lint: an acknowledgment that presumes valence ("great to hear") is allowed only on valence=positive. valence=negative plays a fixed sympathetic fragment plus "Is now a bad time? I can call another day", which routes to callback_request or a polite end (lead suppressed). valence=unknown gets a neutral wording. Add a negative-icebreaker red-team stratum, and include mismatched valence fills in the per-call harm audit.

## A5

A road-noise/hands-free acoustic flag (per-utterance, non-identifying per R118) adds a safety check question.

## A6
DEFENSE: The fallback does not book unknown slots. R41 says the agent "books only the confirmed one", so a caller who can't state a time gets no booking. R111/R121 route repeated unintelligible turns with clear speech energy to an ACCESS_PATH or a human, and "never suppresses redial" covers only disability access. R108 already handles a garbled stop: overlap residue with stop-adjacent tokens ("calling", "off") triggers the R24 check at once, and the post-call sweep marks such calls suppress-pending until a human reviews them. R113 suppresses redial on any unresolved unclear in the closing turns. What's missing is extending that review to every unintelligible turn, not only overlapped ones.
EXISTING ELEMENTS: R41 books only confirmed time; R108 stop-adjacent residue → R24 check + suppress-pending; R113 unresolved-unclear suppression; R111/R121 ACCESS_PATH; R137 channel class; R138 pending_sweep lock
NEW HARDENING: NEW: a call that ends on unintelligible fallback books nothing. It ends with "I'm having trouble hearing; I'll let you go". The number stays under R138's pending_sweep lock until a human listens to the unintelligible spans for opt-outs. Any stop-adjacent fragment means DNC.

## A7

## A8

R89 bans any request for SSN, DOB, bank, card or credit data. R89 also gives verify_agent, which sends an outbox text "from registered short code to verified number" so the caller can check us out-of-band. R146 accepts an address plus a surname token, so the ask is small. The real gap is that a principled refusal has no event, and the anti-phishing wording is vague enough to look contradicted.
EXISTING ELEMENTS: R73 challenge-response IDENTITY; R89 anti-phishing fragment + SSN/DOB/bank lint + verify_agent short-code text; R146 token-set matcher; R30 INBOUND_OPEN; R162 independent identity sources

NEW lint: the anti-phishing line lists exactly what we never ask for ("Social Security, bank or card numbers") rather than "sensitive information".

## A9
DEFENSE: Status is already deterministic. Nothing is "sold" until the vendor webhook moves the call to SALE_SIGNED (R17, R60). The CRM records no sale before signature. Every closing fragment is a human-approved, lint-checked fragment, so "welcome aboard" exists only if a reviewer passed it. I accept that the lint has no status rule, and I add one.
EXISTING ELEMENTS: R17/R60 SALE_SIGNED only on webhook, SALE_PENDING; R18 banned-claims lint (TSR-mapped); R141 mailed notice with cancel instructions; R76 CANCEL; R120 delivery-verified disclosures

The CONTRACT_SENT closing fragment must say "Nothing is final until you sign. After signing you can cancel within {cancel_window}" (policy-table key). NEW: unsigned-envelope reminders repeat this wording, and their rate is a Tier A metric.

## A10
DEFENSE: The goodbye is not one-way. R108's yield rule stops any playout, the closing included, on near-end energy and enters PAUSE, so "wait, actually" takes the turn. R66's post-call sweep is "lexicon + GLOBAL re-run", and GLOBAL includes cancel_or_rescind, not only DNC. R113 makes the teardown sweep mandatory before purge and fails closed. Even a missed cancel happens before signature: CONTRACT_SENT is only an envelope, and R17 plus the cancellation window protect the caller. The real gap is that the sweep's non-DNC hits have no routed action.
