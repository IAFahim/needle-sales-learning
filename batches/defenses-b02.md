## A1
DEFENSE: The design never limited list scrubbing to federal law. R8 puts "state mini-TCPA rules as facts rows" in the pre-dial gate. R70 builds a "pre-dial candidate jurisdiction set with most-restrictive-wins" and checks "invariants across all profiles". The Compliance gates are a "per-jurisdiction regulation profile, most restrictive wins". A state registry is a state mini-TCPA rule, so it belongs in those rows. The attacker is right on one point. The final plan's summary line says only "national/internal DNC" and never names state registries or their separate exemption wording. We close that gap explicitly below.
EXISTING ELEMENTS: R8 pre-dial deterministic gate ("state mini-TCPA rules as facts rows"); R70 candidate jurisdiction set, most-restrictive-wins, invariants checked across all profiles; Compliance gates per-jurisdiction regulation profile; certificates expire when a cited policy row changes.
NEW HARDENING: NEW: The regulation profile gets a state_dnc_registry row for each state that runs a list (IN, TX, CO, PA, MO and others). Each row names its own exemption predicate and is never mapped to federal PEWC. The gate scrubs every candidate jurisdiction's list before each dial. If a list is stale or unavailable, or its exemption can't be proven from the consent artifact, the number is not dialed. Model-checked invariant: no DIAL edge unless every candidate state's registry check passes.

## A2
DEFENSE: Every redial already passes the per-number gate. R74 puts a "per-number consent gate in deterministic dialer", so the WAITING_FOR_SIGNATURE callback is not a free pass. Consent has one ledger, and revocation only has to reach it. Many voice paths already feed it: the stop lexicon, GLOBAL, DTMF opt-out (R75), request_dnc_policy (R84) and the post-call sweep. The gap is real, though. Texts and emails sent to channels the outbox opens (the e-sign SMS, the R89 short code, the written DNC-policy mail) are not wired into that ledger. Under 64.1200(a)(10) those are "reasonable means".
EXISTING ELEMENTS: R74 per-number consent gate (PEWC artifact) in the dialer; R66 post-call DNC sweep before any redial; R75 DTMF opt-out; R84 request_dnc_policy + outbox; R89 registered short code; pre-dial gate on every attempt.
NEW HARDENING: NEW: revocation intake bus. Every inbound channel feeds one revocation classifier: replies to any number or short code we or our vendors send from (the e-sign vendor is contractually required to forward replies and STOP events by webhook), email, web form, installer and CRM notes. The classifier is the stop lexicon plus the GLOBAL stop model, run on the text. A hit writes the DNC ledger within 1 business day (well inside the 10 allowed). Any non-matching reply goes to a human-review queue. The ledger is re-read at the moment of every dial, scheduled callbacks included. Channel fault-injection tests are Tier A.

## A3
DEFENSE: The design already keeps exactly the material needed to rebuild what was played. R67 says "immutable retained bundles", and every session is stamped with its bundle content hash. A rollback changes which bundle new calls use, not whether old bundles exist. R59 says the wording is "chosen deterministically and logged". R39 writes "per-segment playout marks". R74 keeps the PEWC artifact with timestamp, seller and disclosure version. So the exact message can be rebuilt bit-identically, and the consent record is kept. No-retain (R40) covers the caller's speech, not the agent's own output or call metadata. The gap is that retention periods and storage for these records are never stated.
EXISTING ELEMENTS: R67 immutable retained bundles + session bundle hash; R59 logged deterministic wording choice; R39 playout marks; bit-identical replay; R74 PEWC artifact; R40 NO_RETAIN scope.
NEW HARDENING: NEW: TSR record set kept for 5 years or more in WORM storage, whatever the privacy mode. It holds the CDR (real number, time, duration, disposition, caller ID), the consent artifact, the per-call render log (fragment id, wording id, slot fills, playout marks) and the rendered agent-side audio. Every fragment wording is archived as a "unique message". Bundles can never be deleted within the retention period. No-retain is redefined as caller-content only.

## A4
DEFENSE: Two things limit the exposure. In NO_RETAIN calls (R40) no recording was ever lawfully made. There is no duty to create evidence, so nothing was spoiled. For retained calls, R7 makes "deletion = data operation", and A3's WORM render log keeps the agent side. But the attacker is right on two points. No event detects a legal threat. And surrogate replacement and scrubbing run blind to any preservation duty. A bit-identical replay is not the original record.
EXISTING ELEMENTS: R40 NO_RETAIN; R7 deletion as data operation, PII surrogates; R67 immutable bundles; R66 post-call transcript sweep; R52 UNEXPECTED_EVENT; R56 request_human.
NEW HARDENING: NEW: legal_threat GLOBAL event, fired by a deterministic lexicon (lawyer, attorney, sue, lawsuit, class action, demand letter) or by Needle. It plays a fixed neutral fragment, offers a human, ends the pitch and sets a legal_hold flag. The flag freezes every deletion, surrogate and scrub job for that session and number, preserves the original audio and transcript, and alerts legal. The number also goes on the internal DNC. The post-call sweep and inbound complaint or demand channels set the same hold. Hold-vs-deletion fault-injection tests are Tier A.

## A5
DEFENSE: The scenario's premise is not in the design. The self-echo filter (R38) matches the "incoming transcript vs agent's rendered text in a time window". It compares text, not voices. speaker_change() (R9) is a Needle event over words ("this is his wife"), and identity is "challenge-response (caller states name/address, deterministic match)" (R73), so it is not voice-based. Prosody (R80) is an "F0 final-rise detector -> <rise> token". That is a single per-utterance pitch slope, which can't identify anyone. Replay (R67) uses the bundle and transcripts, not embeddings. The design computes no voiceprint. Still, nothing forbids one, so we lock that down.
EXISTING ELEMENTS: R38 text-based self-echo filter; R9 speaker_change() Needle event; R73 challenge-response identity; R80 F0 final-rise token; R98 media/far-field features; R67 replay from bundle.
NEW HARDENING: NEW: Biometric feature ban as a build check. Front-end features may only be per-utterance and non-identifying (F0 slope, direct-to-reverberant ratio, energy). They are computed in memory and discarded. They are never persisted, never cross-utterance, and include no speaker embedding or diarization identity vector. Any vendor ASR or diarization setting that produces speaker embeddings is disabled and pinned in the bundle (R68). A published biometric non-collection and retention statement covers IL and TX.

## A6
DEFENSE: There is no "medical_dependency" label in the design. sensitive_event types are coarse routing classes (R19). Their only purpose is a scripted exit with "no pitch", which in itself serves the consumer. R7 limits data collection, and the vulnerability counter (R15) only routes the call. The gap is real, though. Retained transcripts and gold sets (R7, R40) keep the spoken health content and the event label, and the per-release finetune union trains on them without MHMDA consent.
EXISTING ELEMENTS: R19 sensitive_event + scripted exits; R15 vulnerability counter; R7 data minimization, PII surrogates, deletable gold sets; R40 retention-consent flag gate in build pipeline; regulation profile per jurisdiction.
NEW HARDENING: NEW: Health-data quarantine. When sensitive_event(medical_*) fires, or a health lexicon hits in post-call processing, those turns are redacted at span level from every retained transcript, audit sample and training set. The persisted label becomes a type-less "sensitive_exit". In MHMDA, NV and CT health-data profiles, no health-derived data is kept beyond the in-memory routing decision. The medical sensitive-event classes are trained only on synthetic and consented data. The build pipeline rejects health-tagged real spans. A health-data privacy policy is published.

## A7
DEFENSE: Several parts are already in place. The contract is only binding after the vendor reports a completed signature (R60). Install waits out "the longest cancellation window" (R17). The design already lists a landline/mailed fallback as an open item (R22). But the attacker is right that no step ensures ESIGN 7001(c) consent "reasonably demonstrates" access, and that no accessible alternative is offered.
EXISTING ELEMENTS: R17 CONTRACT_SENT/install waits for cancellation window; R60 webhook-only status; R22 OTP + open landline fallback; R42 RELAY_MODE accessibility metric; R56 request_human; R88 capacity flags -> human review.
NEW HARDENING: NEW: First, an ESIGN demonstration step: the envelope's consent page asks the signer to enter a code shown only inside a sample record in the contract's own format. Second, the vendor must meet WCAG 2.1 AA with tagged PDFs, and is tested with screen readers. Third, before CONTRACT_SENT the agent asks a fixed question: e-documents, or paper by mail or with a consultant? Paper, or any stated access need, routes to a mailed or in-person signing with a human. Finally, the cancellation clock starts at verified delivery of the disclosures, and install is gated on that delivery.

## A8
DEFENSE: The fallback is not a dead end. "Clarify once, then fallback" leads to "deterministic fallback (callback or human)". R56 request_human means a "warm transfer to staffed queue ... else book consultant call", and a human can quote. Endpointing already lengthens for incomplete turns (R25). Rising confusion lengthens thresholds (R15). RELAY_MODE (R42) covers relay users. Still, two things are true. The fallback could pick an AI callback that ends the same way. And audits are stratified by dialect, not by disability.
EXISTING ELEMENTS: Uncertainty fallback "callback or human"; R56 request_human warm transfer/consult; R25 incomplete() longer thresholds; R15 thresholds lengthen; R42 RELAY_MODE accessibility metric; R26 per-group bounds.
NEW HARDENING: NEW: Accessibility routing. A call with repeated unintelligible turns but clear speech-present audio goes to a human warm transfer, or a booked human consult. Such a call is never given an AI callback, and its lead is flagged human-only. Callers can also choose a DTMF path or a text/web path. A speech-disability stratum is built from consented atypical-speech recordings. "Reached quote or human" parity for that stratum becomes a release blocker.

## A9
DEFENSE: The design already gates on per-state licensing. R47 says "where salesperson registration applies (e.g. CA HIS), call runs lead-gen mode", and the regulation profile is "most restrictive wins". The outbox texts (CONTRACT_SENT SMS, appointment texts) leave only through deterministic gated effects (R13, R55). Any per-state row therefore covers them automatically. Fair point: that row is not there yet. There is a contractor-registration row (HIS), but no telemarketer registration and bond row, and no rule that texts count.
EXISTING ELEMENTS: R47 jurisdiction profiles / lead-gen mode; Compliance gates regulation profile most-restrictive-wins; R70 candidate jurisdiction set; R13/R55 outbox effects; certificates expire on policy row change.
NEW HARDENING: NEW: seller_registration rows for every state (TX ch. 302 as amended by SB 140, UT, WA and others) record registration id, bond or security, and expiry. These are pre-dial guards and outbox guards, and texts count as solicitation. If registration is missing or expired in any candidate state, nothing is dialed or texted there. A 30-day expiry alert runs. Model-checked invariant: no DIAL and no SMS effect without valid registration in each candidate state.

## A10
DEFENSE: The scenario breaks an existing rule: "no Needle tool can create outbound contacts (build check)" (R74). The caller cannot speak a co-owner's number into the system. R88 builds the signer list from "record-owner lookup on validated address" plus "lender stipulated signers". The lender runs its own identity check on each borrower. The OTP goes to the dialed number (R22), not to a dictated one. The attacker is right on one point: the design never says where a non-dialed co-owner's contact comes from, or how that person proves identity.
EXISTING ELEMENTS: R74 no outbound contacts created by Needle; R88 record owners + lender signers, co-owner notice, capacity flags -> human review; R22 OTP to dialed number; R60 webhook status; R17 install waits for cancellation window.
NEW HARDENING: NEW: Each signer needs independently sourced contact data: their own consent or lead record, or a lender-KYC-verified phone. Signer phones and emails must all be distinct. Any lien- or UCC-creating envelope requires the vendor's ID verification for each signer (document + selfie). If that fails, the co-owner signs before a notary or consultant at the site survey. No lien or install proceeds until every owner is independently verified.
