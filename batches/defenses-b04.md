# Defenses, batch b04

## A1
DEFENSE: The skipped READ_BACK would still have to get past checks that are separate from the transition table. confirm_order/accept_offer commits "only the quote hash read back immediately before the yes" (R49), and "Read-back bound to config hash" (R23). Disclosure flags are "written only by playback engine on uninterrupted completion" (R39), and the playback engine is a separate component from the generated C. The lexical commit gate (R87) is aimed at "this read-back question id". So a backdoored QUOTE->CONTRACT_SENT edge reaches the outbox with no read-back hash and no playout mark. Property-based random walks (R49) and fault injection run against the built artifact, not just the graph. That said, the attack is right that nothing formally proves the binary refines the graph.
EXISTING ELEMENTS: R49 accept_offer commits only read-back quote hash; R23 read-back bound to config hash; R39 playback-engine-written mandatory flags; R87 lexical commit gate on read-back question id; R69 own checker over exported graph; property-based random walks; bit-identical replay; content-hashed bundle.
NEW HARDENING: NEW: (1) Translation validation. The build enumerates the compiled binary's (state, event, abstract-guard) transition relation by exhaustive harness execution and diffs it against the exported graph; any extra edge fails the release. (2) Independent runtime trace monitor. A separately written, non-generated automaton of the graph checks every committed transition, and the outbox refuses CONTRACT_SENT/effects whose trace is not in the graph language. (3) StateSmith and compiler are vendored by hash, builds are reproducible, and a diverse double-compile is done with two toolchains.

## A2
DEFENSE: Recertification does not mean 300,000 new live calls. A certificate's empirical content is the input-to-decision behavior of (weights, tool list, graph). The design already has the tools to show a patched runtime preserves that behavior: "cross-node bit-identical replay before release" (R53), replay of "all states' frozen human-audited gold sets" (R3), the daily golden-audio canary, and "immutable retained bundles". If the patched runtime produces bit-identical outputs on every audited call ever retained, the 1e-5 evidence carries over unchanged. Most CVEs (OpenSSL, glibc networking, drivers) sit outside the inference math. States that do diverge drop to the existing deterministic fallback, so the fleet never goes dark.
EXISTING ELEMENTS: R53 certificate key incl. runtime build/hardware class + cross-node bit-identical replay; R3 frozen gold-set replay per candidate build; daily golden-audio canary; R67 immutable retained bundles, blue/green; R25/R36 deterministic fallback per state.
NEW HARDENING: NEW: (1) Equivalence-based re-keying. A patched runtime inherits a state's certificate if, on that state's full retained gold set plus canary corpus, outputs are bitwise identical (tokens, top-1/top-2 margin decisions). Only diverging states recertify; they run on fallback meanwhile. (2) Minimal TCB. Needle inference runs in a sandbox with no network or PII store access, so perimeter patches (TLS, OS network stack) are outside the certified build hash. A security emergency can always pick fallback for affected states within hours.

## A3
DEFENSE: A forged "completed" event does not install anything. "Install waits out the longest cancellation window" (point 11), the success label is "joined later from CRM/install records" (R50), and "No CRM sale/crew before signature" (R17). The envelope goes to all record owners and lender signers, "gated by SMS OTP to dialed number" (R22/R88), so real signatures exist on the vendor side to check against. Vendor events enter as a "versioned status enum" (R60) through WAITING_FOR_SIGNATURE substates with "holds + idempotency keys" (R55). Duplicate replays are already deduplicated. The real gap is authentication and envelope binding, which the design does not spell out.
EXISTING ELEMENTS: R60 status only from vendor webhooks/APIs, versioned status enum; R55 WAITING_FOR_<effect> substates, idempotency keys; R17 no CRM sale/crew before signature; point 11 install waits longest cancellation window; R88 signer list = record owners + lender signers; R22 OTP-gated envelope.
NEW HARDENING: NEW: (1) Webhook is a wake-up hint only. On any inbound event, the system pulls envelope status from the vendor API with its own credentials, and only that pulled status becomes a StateSmith event. (2) Mandatory HMAC verification, mTLS/IP allowlist and timestamp windows, with a build check that the HMAC flag is enabled. (3) Envelope id is stored in the session's outbox record. Unknown or mismatched ids are rejected, and state changes must be monotonic (void after completed goes to human review, never auto-kill).

## A4
DEFENSE: Channel-induced WER errors still hit the design's ASR-agnostic checks. "Tier A numbers confirmed digit-wise" (R26) and "critical-slot read-back" (R2) let the caller catch the error. The "argument grounding gate" (R61) and the "ASR-confidence/no-speech pre-gate" route low-confidence numbers and negations to clarify. The commit gate is "lexical" and "closed re-ask" on anything ambiguous. "Continuous audited sampling with per-state drift alarms" (R33) reverts a state to fallback when clarify or error rates move. The attack is right that the certificate pins ASR software, not the acoustic channel, so an afternoon of degraded quality could pass before drift statistics accumulate.
EXISTING ELEMENTS: R26 digit-wise confirmation and per-dialect strata; R2 critical-slot read-back; R61 argument grounding gate; ASR-confidence pre-gate; R77/R87 lexical commit gate and closed re-ask; R33 per-state drift alarms with fallback; R68 golden-audio canary.
NEW HARDENING: NEW: The channel class is part of the certificate key: codec, sample rate, carrier route and transcoding hops, read per call from SDP/RTP and bandwidth estimation. Gold sets and per-dialect bounds are stratified by channel class. A call on an uncertified class runs only states certified for it, and commit and numeric states otherwise go to callback fallback. The golden-audio canary runs through each trunk's codec chain. Per-trunk confidence and clarify-rate alarms fire within minutes, not on daily statistics.

## A5
DEFENSE: The design already makes a redial wait on prior outcomes: "post-call DNC sweep of every transcript ... before any redial" (R66) is a barrier, not a background job. Mid-call opt-outs are handled at once: "Stop = union of deterministic lexicon and Needle GLOBAL" ends the call, and DTMF opt-out does a "DNC write" at the root (R75). Caps are evaluated by the deterministic pre-dial gate "for the most restrictive candidate jurisdiction" (R41, R70), and Florida's three-per-24h is a regulation-profile row. The attack correctly notes the gate is specified as logic, not as a concurrency primitive.
EXISTING ELEMENTS: R66 post-call DNC sweep before any redial; R75 DTMF DNC write at root; R41 pre-dial gate enforces per-state frequency caps; R70 most-restrictive-wins jurisdiction set; R74 per-number consent gate in deterministic dialer.
NEW HARDENING: NEW: A linearizable dial permit. Each dial must win an atomic check-and-reserve on a strongly consistent store, sharded by number (serializable transaction or CAS lease; never a read replica). The reserve checks DNC, consent, the rolling-window counter including in-flight reservations, and a per-number "pending_sweep" lock. The lock is set at dial and cleared only when the post-call sweep commits. Retry queues and every region use the same permit. If the store is unreachable, dialing fails closed. A model-checked or TLA+ spec of the permit protocol is a release check.

## A6
DEFENSE: Hours are already conservative by design: "calling hours and frequency caps for the most restrictive candidate jurisdiction" (point 1), using "address tz (stricter overlap with area code)" (R41), with hour rules as versioned regulation-profile facts rows. The fleet-wide failure needs a wrong clock or tzdata on the dialer. The attack is right that time source and tzdata are outside the content-hashed bundle.
EXISTING ELEMENTS: point 1 pre-dial gate, most-restrictive calling hours; R41 address tz with stricter overlap with area code; R70 candidate jurisdiction set; R67 content-hashed bundle, blue/green; daily golden-audio canary; budget breach -> rollback.
NEW HARDENING: NEW: (1) tzdata is pinned inside the certified bundle, and the dial gate uses only that copy. (2) Time comes from at least three authenticated NTS sources. The gate refuses to dial when measured offset or uncertainty exceeds a small bound (fail closed). (3) Two independent tz implementations compute local time, and any disagreement blocks the dial. (4) A guard band: the lawful window shrinks (e.g. 30 min each end), widened on DST-transition days. (5) The gate is tested by property over every zone across DST boundaries. A daily canary dials a test number per zone.

## A7
DEFENSE: The design states that facts carry effective dates: "versioned, owned facts table with effective dates" (design runtime), and "certificate = (state, weights hash, facts-table version)" (R3). A restored bundle's certificate is tied to a policy-table version that is no longer current, so under the design's own keying it is not valid for today's facts. "Certificates expire when a cited policy row changes" applies at expiry time, not at rollback time. Derived values are "computed from versioned inputs on read" (R23), so a quote checks row validity at render time. The attack still exposes that rollback is not specified as policy-aware.
EXISTING ELEMENTS: facts table with effective dates; R3 certificate keyed on facts-table version; certificates expire when cited policy row changes; R23 derived values computed on read from versioned inputs; R67 immutable retained bundles; R47 lead-gen mode; fallback.
NEW HARDENING: NEW: (1) The policy table is forward-only and outside rollback. Rollback restores graph, weights, fragments and ASR only, and always runs against the current effective policy table. (2) Every retained bundle is continuously re-checked (lints, fact-key coverage, gold replay) against the current table. Rollback targets only a bundle marked compatible, else QUOTE/READ_BACK states go to lead-gen or callback fallback. (3) Recalls and withdrawn rows are tombstones that no bundle can cite. (4) The runtime refuses any fact row outside its effective_from/until window.

## A8
DEFENSE: A SIM-swapper on this design still faces checks that do not ride the phone. The lender "runs application and decisions" (its own KYC/CIP). Signers are "all record owners + lender stipulated signers" from "record-owner lookup on validated address" (R88). "Capacity flags ... -> human review path." Install "waits out the longest cancellation window". The voice channel never collects SSN or bank data (R45, R89), so breached-data KBA unlocks nothing financial on its own. RND blocks reassigned numbers. The attack is right that the identity challenge and OTP share one factor (the number), and the design has no port or SIM-change signal.
EXISTING ELEMENTS: point 1 Reassigned Numbers Database; R73 challenge-response identity; R22 OTP to dialed number; R88 record-owner signer list and capacity flags; lender runs application/decisions; R84 print-and-mail API via outbox; point 11 install after longest cancellation window; R45/R89 no SSN/bank/card on voice.
NEW HARDENING: NEW: (1) A carrier SIM-swap/port-out check (number-verification API) before IDENTITY and again before the OTP. Any change within N days -> no sale on the call, lead-gen plus human verification. (2) An out-of-band mailed notice to the validated property address (existing print-and-mail outbox) for every record owner, with contract summary and cancel instructions. Install is blocked until the mailing has had time to arrive within the cancellation window. (3) Lien/UCC filing is held until the window closes.

## A9
DEFENSE: The first agent audio does not need Needle. OPENING "waits for callee" and then plays the "compiled, unskippable" PREAMBLE, a pre-rendered certified fragment that the deterministic machine can start on the callee's greeting with no inference. So the two-second connection rule is met by deterministic playback even when the fleet is degraded. Mid-call, "state failing its live error bound -> deterministic fallback" and "call budgets -> WRAP_UP" end calls gracefully. The dial list is limited to "prior-express-written-consent and inbound/warm leads" (R59), which is not mass predictive overdial. The attack is right that pacing is not coupled to fleet capacity, and callback bookings can exceed staff.
EXISTING ELEMENTS: OPENING waits for callee; R31 compiled PREAMBLE fragment; R39 playout marks; R69 call budget counters -> WRAP_UP; deterministic fallback; R55 WAITING_FOR_<effect> with CONFLICT for bookings; R59 PEWC/warm leads only.
NEW HARDENING: NEW: (1) Admission control. A dial permit also requires a reserved Needle capacity token from live fleet health (p95 latency, healthy hosts), so lost capacity stops new dials first and in-flight calls keep priority. (2) A per-campaign rolling 30-day abandonment counter in the pre-dial gate, with a hard stop well below 3%. (3) Pacing 1:1 by default, with no overdial. (4) Callback/consult bookings are drawn from a staffed-capacity calendar. When full, the booking returns CONFLICT, and the agent offers a written proposal and later date instead.

## A10
DEFENSE: The audio is less rich than claimed. Data minimization means the agent "collects only coarse facts ... no account/income/credit" (R7). The "payment-data redactor on ASR stream (text + audio mute)" (R45) and lint bans on requesting "SSN, DOB, bank/card data" (R89) keep the most dangerous items out of recordings. "NO_RETAIN mode" applies without affirmative retention consent, and the "build pipeline rejects transcripts lacking retention-consent flag" (R40). Real utterances live "only in deletable gold sets" (R7). Certification needs audited samples from consented calls, not all calls. The attack is right that outsourced listening is still a large exposure surface.
EXISTING ELEMENTS: R7 data minimization, PII surrogates, deletable gold sets; R45 payment redactor with audio mute; R89 lint bans SSN/DOB/bank requests; R40 NO_RETAIN and retention-consent flag gate, processors barred from training; R74 third-party contact redaction.
NEW HARDENING: NEW: (1) Labeling runs only in a controlled enclave: in-house or vetted staff, streaming playback in a VDI with no download, per-clip watermarking, access logging and anomaly alerts. (2) Labelers get only the clipped turns under audit. IDENTITY-state answers and address segments are muted by known state timestamps, and audio is decoupled from name and number. (3) Raw audio has a retention TTL, after which only canonical text plus features remain. The bit-identical replay and canary corpora use consented or staff-recorded audio. (4) Certification sampling draws only from calls with retention consent.
