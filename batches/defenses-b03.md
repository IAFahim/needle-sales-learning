# Defenses, batch b03

## A1
DEFENSE: Shadow logs are never the release gate. The gate is on-policy: R20 says certification comes from "the disclosed agent's own build-phase calls", and R36 retires the big model per state only after an "audited error bound over N consecutive calls + fallback rate < X% + A/B handoff lift", which requires Needle actually driving those calls. Shadow agreement only nominates a state for that live trial. Compounding is also capped structurally: both policies walk the same compiled graph, every qualification-critical slot is read back (R2, "a single-turn Needle error becomes a caught correction"), and commit needs a lexical gate independent of Needle (R87). The point is fair, though, that "whole audited call traces" must mean Needle-driven traces only, so I am stating that explicitly below.
EXISTING ELEMENTS: R20 on-policy data (DAgger-style); R36 per-state big-model retirement rule; R2 deterministic critical-slot read-back; R2 "states that cannot reach the bound... route to deterministic fallback"; R66 per-call budgets on whole audited call traces; R87 lexical commit gate; R33 continuous audited sampling; blue/green rollback.
NEW HARDENING: NEW: whole-trace Tier A/B bounds may be computed only from Needle-driven (on-policy) calls. Shadow traces are labeled "per-turn nomination evidence" and cannot enter the gate. Promotion runs as a staged ramp: shadow -> Needle-driven canary cohort with 100% human audit of every trace -> widened cohort. The bound is recomputed at each step, and any breach sends the state back to fallback.

## A2
DEFENSE: The attack assumes a renormalized post-mask margin is the only confidence check. Three other layers make that confidence irrelevant at COMMIT. First, the commit gate is "lexical over final ASR tokens (independent of Needle output)" (R87), and it accepts only a short, direct affirm from a narrow set aimed at the read-back question id (R77, R81). A truly novel utterance contains no such affirm, so nothing commits whatever Needle outputs. Second, the GLOBAL and LOCAL passes are separate (R34), so stop and request_human never compete with local tokens. Third, R19's max-softmax OOD backstop exists. The real gap is where that score is read, and I fix it below.
EXISTING ELEMENTS: R87 lexical commit gate; R77 narrow unambiguous affirm set + closed binary re-ask; R81 short direct answer check; R80 <rise> exclusion; R19 max-softmax OOD backstop -> unclear(); R53 top-1/top-2 margin; R34 two-pass GLOBAL/LOCAL; R85 READ_BACK invariant.
NEW HARDENING: NEW: (1) Each event name is a single reserved vocabulary token, so no event shares a first token with another and the margin sees the whole decision. (2) The OOD score is the pre-mask probability mass on the allowed event tokens. If off-schema mass is above a per-state threshold, the turn goes to unclear() before constrained decoding runs. (3) Instead of greedy masked decoding, each of the state's finite events (with arguments) is scored by its full-sequence log-likelihood, and the margin uses those unnormalized scores. (4) A "novel utterance at COMMIT" red-team stratum checks that off-schema mass routes to clarify.

## A3
DEFENSE: The per-state bounds are allocations of one per-call budget (R2: "per-state budgets derived from it"), and that budget is checked on whole audited call traces (R66). That single release-level test is the one the published claim rests on, not 5,000 separate ones. Tier A states also replay frozen human-audited gold sets plus sealed holdouts and a post-release shadow window (R3), and continuous audited sampling with drift alarms (R33) catches a lucky pass in production. Still, the attack correctly points out that per-state tests with retry-until-pass and no correction would inflate false certifications. Below I make the statistics valid by construction.
EXISTING ELEMENTS: R2 per-call harm bound with derived per-state budgets; R66 per-call per-severity budgets on whole traces, 95% upper bound, breach -> rollback; R3 sealed holdouts for Tier A + post-release shadow window; R33 per-state drift alarm reverting to fallback; R26 per-group bounds.
NEW HARDENING: NEW: (1) A family-wise alpha is set per release (Bonferroni or Holm across every state x stratum x tier test). The published claim is the corrected one. (2) Tuning and promotion use an exploration sample. Certification uses a fresh confirmatory sample collected after the promotion decision, and it is used once. (3) A state that failed keeps its failing evidence: retries run as a pre-registered sequential test (alpha-spending) on cumulative data and cannot restart from zero. (4) Promoted states face a mandatory confirmation window on live traffic before the release-level claim is published.

## A4
DEFENSE: Held-out synthetic accuracy certifies nothing: "Synthetic data trains Needle and finds bugs; it never certifies" (R2). Only real, human-audited on-policy calls count (R20). Both examples also fail for structural reasons. "please stop" sits in a sentence about money, but stop is decided in the GLOBAL pass, whose tool list has no objection_price (R34), so a money word cannot outvote it there. It is also unioned with the deterministic lexicon (R66), which flags "please stop" outright. "don't bother me again" matches the R93 dialect/negation patterns, and any miss is caught by the post-call DNC sweep before any redial. Real data is never replaced (R33), per-source caps (R51) limit any one generator, and the red team is model-diverse with human-written seeds (R97).
EXISTING ELEMENTS: R2 synthetic never certifies; R20 on-policy real calls; R34 GLOBAL/LOCAL two-pass; R66 mid-call stop = union of lexicon + GLOBAL, post-call DNC sweep; R24 Tier 1 lexicon; R93 dialect stop patterns; R33 real data never replaced; R51 per-source caps; R97 model-diverse red team + human seeds.
NEW HARDENING: NEW: an artifact audit runs each release. A surface-only probe (length, first token, politeness markers, label-keyword bag) is trained per data source. If it predicts labels above a set baseline, that source is rebalanced or regenerated. Counterfactual minimal pairs (same style and keywords, different label, e.g. money words + stop, polite non-stop) are required in training and as a Tier A red-team stratum. Lexicon-vs-Needle disagreement on real traffic queues automatically for audit.

## A5
DEFENSE: The rise token gates COMMIT through deterministic code, not through what Needle learned: "affirm with <rise> excluded from commit set" (R80) sits inside the lexical commit gate (R87), which is independent of Needle. Both failure modes stay safe. Detector false rises on uptalk "yes" block the commit and force a closed re-ask (R77), costing only a turn. A missed flat question still has to be a short, direct, lexical affirm to the read-back question id (R81), which questions like "and that's the total?" aren't. Certification is on real live calls with human audio labels (R26), so any skew shows up in the gate numbers.
EXISTING ELEMENTS: R80 prosody front end + <rise> exclusion; R87 lexical commit gate independent of Needle; R77 closed binary re-ask; R81 short direct answer check; R26 gold labels from humans listening to audio; R68 training and certification on canonical text from the pinned front end; R2 real-traffic-only certification.
NEW HARDENING: NEW: (1) The big model may not write <rise> tokens. Prosody tokens in training data come only from running the pinned detector on audio: real calls, or synthetic text rendered by TTS with varied intonation and dialect uptalk and passed through that same detector. (2) If that coverage is insufficient, prosody tokens are stripped from Needle's input entirely and consumed only by the deterministic gate. (3) The detector's false-rise and missed-rise rates per dialect stratum become Tier A metrics, and uptalk-"yes" is a red-team stratum.

## A6
DEFENSE: Contamination can't inflate the gate, because the gate is fresh real traffic: certification needs "held-out + fresh calls" on live traffic (R2), sealed holdouts for Tier A (R3), and continuous post-release audited sampling (R33). None of these can be in a training set that was frozen before they were collected. The golden-audio canary (R68) is a bit-identical determinism check on the pinned front end. It asks whether output changed, not whether it is right, so memorizing it proves nothing and fools nothing. Past red-team pass rates are regression checks, not robustness evidence. The attack still has a point, though: the design states no dedup rule between pools. I add one below.
EXISTING ELEMENTS: R2 real-traffic-only certification on held-out + fresh calls; R3 frozen human-audited gold sets + sealed holdouts + post-release shadow window; R33 continuous audited sampling; R68 daily golden-audio canary (diff -> block); R66 budget on whole audited traces.
NEW HARDENING: NEW: (1) Every evaluation pool (sealed holdouts, gold sets, canary audio, open red-team items) is content-hashed and placed on a training denylist, enforced by a build check. (2) A near-duplicate filter (MinHash plus embedding distance) and a generator-prompt lineage check remove training items within a set distance of any eval item. (3) Red-team items that get fixed move to a "regression" suite reported separately. Each release requires a fresh, never-trained red-team round, and only its pass rate counts as robustness evidence.

## A7
DEFENSE: R51 quarantines rare *repeated* n-grams, meaning a rare string recurring across many items with a skewed label, which is the signature of a planted trigger. Natural dialect forms like "finna" or "ion" appear across many independent callers, sources and labels. Quarantine is review, not deletion, and minority speech is protected from several sides: per-dialect error bounds are release blockers (R93), gold sets are stratified by dialect with per-group bounds (R26), Multi-VALUE dialect transforms run on all synthetic data (R93), and stop is unioned with a deterministic lexicon that includes dialect patterns (R66, R93). Starvation would show up as a failing per-group bound, which blocks release rather than hiding the problem.
EXISTING ELEMENTS: R51 rare repeated n-gram quarantine + per-source caps + trigger-fuzzing invariance tests; R93 dialect stop patterns, Multi-VALUE transforms, per-dialect bounds as release blockers; R26 dialect-stratified gold sets; R16 language detector + Spanish handoff; R33 real data never replaced.
NEW HARDENING: NEW: (1) Quarantine requires source concentration as well as rarity and repetition: the n-gram's items come from few sources or numbers with label skew. (2) A curated dialect/code-switch allowlist (Multi-VALUE features, AAE and Spanglish lexicons) is exempt from automatic quarantine. (3) Quarantine rate per dialect stratum is tracked, and a disparity alarm blocks release. (4) Quarantined real items get human review within a release cycle and return to training if benign. Code-switched "no, gracias" is also a stop lexicon entry.

## A8
DEFENSE: Stratification applies only to the audit gold set, never to the runtime or the customer record. Gold sets live in deletable stores with PII surrogates (R7). Prohibited-basis fields carry tags and a build invariant that bars their use (R46). The strata are dialect/accent, which are linguistic features, not ethnicity. Mis-binning dilutes per-group rates, but the per-call bound across all calls still holds (R66), and matched-pair tests (R46) probe disparity without any per-caller label. The attack is right that the binning method is unspecified and that storing a label is sensitive, so I specify both below.
EXISTING ELEMENTS: R26 gold labels from humans listening to audio, stratified by accent/dialect with per-group bounds; R7 PII surrogates, real utterances only in deletable gold sets; R46 prohibited-basis field tags + build invariant + matched-pair fair-lending tests; R93 per-dialect bounds as release blockers; R66 per-call budgets.
NEW HARDENING: NEW: (1) Strata are defined by observable linguistic features (a Multi-VALUE feature checklist, L1-accent family) annotated by two trained auditors. Inter-rater agreement is measured, and the measured confusion matrix corrects per-group estimates. (2) Labels exist only on audit records under surrogate IDs. They never go to CRM or runtime and are never a model input, and they are deleted with the gold item. (3) A label-free worst-group check runs alongside: error rates over unsupervised clusters of acoustic and ASR-confidence embeddings, with the worst cluster held to the same bound, so mis-binned groups still surface.

## A9
DEFENSE: The scenario's premise that monitoring is "only labeled audited outcomes" on 1% of calls is false for stop, the main Tier A harm. The post-call DNC sweep re-runs the lexicon and GLOBAL pass over every transcript before any redial (R66), giving 100% coverage, and the lexicon is unioned with Needle mid-call. Several 100%-coverage operational signals already exist: fallback and clarify rates (R36), per-fragment repair rates (R48), cancellation rate per branch (R50), and complaint joins (R71). A budget breach triggers rollback to the previous certified artifact (R66). The attack does show that leading, label-free alarms need to be explicit, so I add them below.
EXISTING ELEMENTS: R66 post-call DNC sweep of every transcript, lexicon + GLOBAL union, budget breach -> rollback; R33 per-state drift alarms; R36 fallback rate; R48 per-fragment repair rate; R50 cancellation rate per branch; R71 complaint-linked success label; R68 daily canary; R24 false-stop metrics.
NEW HARDENING: NEW: label-free drift monitors run on 100% of traffic: per-state event-mix shift, the clarify and near-tie rate, the distribution of pre-mask off-schema mass (see A2), lexicon-vs-Needle disagreement rate, out_of_scope cluster growth, and hang-up-after-turn rate. Alarms use CUSUM/sequential tests. Any alarm triggers (a) an immediate 100% audit surge on the affected states, and (b) for Tier A states, automatic reversion to deterministic fallback until the surge clears. Every lexicon/Needle disagreement queues for human audit.

## A10
DEFENSE: Certified error rates aren't carried over between releases. The certificate is keyed to the weights hash (R3, R53), so each release's rates are re-measured on real human-audited traffic (R2). If release 9 over-fires stop, its own false-stop rate (a Tier A metric, R24) is measured and blocks it, and the same goes for under-firing. Stop is also the union of Needle and the deterministic lexicon (R66), so a Needle prior swing toward under-firing stops can't drop lexicon hits. Over-firing produces safe exits, and R24's resume check handles ambiguous ones. The real gap is that a fixed clarify margin sits on a shifting score scale, which I fix below.
EXISTING ELEMENTS: R3/R53 certificate keyed by weights hash, frozen gold set replay; R2 real-traffic-only certification; R24 false-stop and false-continue rates as Tier A metrics + resume check; R66 lexicon + GLOBAL union, rollback on breach; R53 top-1/top-2 margin threshold; R51 per-source caps.
NEW HARDENING: NEW: each release runs a calibration step on a real, audited calibration split that is kept apart from the certification sample. It fits temperature scaling plus label-shift prior correction (BBSE/EM to deployment event priors measured on live traffic). Margin, OOD and clarify thresholds are then re-set to hit target false-stop and false-commit rates. The calibrated thresholds and the training mix ratios ship in the content-hashed bundle and are part of the certificate key.
